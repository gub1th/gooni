## Goal

Gooni = personal AI notebook → ambient home assistant. **Ambient-loop v2 (2026-07, PRD note #389) collapsed the primitive layer to 6 core tables.** The loop:
1. Every thought — web chat, WhatsApp, Telegram, notes — lands in one append-only log with a uniform ack (no dispatch fork at capture time)
2. The extractor annotates commitment-shaped messages with a glow; Daniel promotes them to Promises with one tap (or dismisses); measurements log to Trackables (web matrix, or an explicit whole-basis chat log tool — NOT auto-extracted)
3. A hover-summoned frosted overlay shows what matters right now (deterministic rankers, no LLM)
4. Memory built from notes/chat in SQLite `memories` table (extract → reconcile via LLM, cosine-retrieved at chat time) — KEPT through the v2 nuke (Daniel's override; chat recall is load-bearing)

Mobile capture via bots: Telegram (live), WhatsApp (live), iMessage (code shipped, awaiting Mac+BlueBubbles). All route through `MessagingChannel` ABC in `app/services/messaging/`.

## Core data model (post-v2)

**5 primitives + Memory:**
- `Note` — universal capture atom. Tags (JSON list, lowercase, deduped) replace Spaces for ALL organization. `excerpt` cached preview; `is_draft`/`is_pinned`/`is_public(_pinned)`. `GET /notes` (flat list, `?tag=` filter), `POST /notes`. (The `status` graduation lifecycle + 5am-batch session cols were dropped in the lean sweep `4d9c44f8f546`.) Two placement cols (migration `884013e244b2`): `log_date` (Date, indexed) marks a **daily-log note** — the log-matrix "note" column, one per date, `daily` tag, `GET /notes/daily?days=&end=` + `PUT /notes/daily/{date}` (empty body → delete = cell-clear); `home_pos` (JSON-text `{x,y}` viewport fractions) marks a **sticky note** parked on the ambient home, `sticky` tag, `GET /notes/sticky`. Both are real Notes (searchable, embeddable) — not new primitives. **Two more subtypes arrived with the focus convergence** (migration `f4c81a92de70`): the `thought` tag (a single logged thought, `parent_note_id` → its batch) and `thought-batch` (a run of thinking; `title` = Claude's third-person label). Same trick as `daily`/`sticky` — tags, not tables. Notes also gained **`topic_id`** (nullable FK → `topics`), a real FK rather than a tag because `Topic` carries a decay curve anchored to `last_touched`, and computing that by LIKE-matching a JSON column would be slow *and* wrong the moment a topic is renamed. Tags stay for every other kind of grouping.
- `Promise` — THE actionable primitive (absorbs Todo/Habit/Focus **and, since the 2026-08-08 focus convergence, Reminder**). `cadence` (`once|daily|n_per_week|permanent_do|permanent_never`), `cadence_target` (N for n_per_week), `is_important` (user-set; overlay input), `parent_promise_id` (self-FK nesting — a "Focus" is a Promise with children), `inferred_due` (local-EOD anchored, naive UTC), `needs_clarification`, `slip_count` (cosine vs past broken), `source_message_id`, deferred `embedding`, plus the two columns absorbed from Reminder (migration `f4c81a92de70`): **`owed_to`** (nullable FK → `focus_people`; null = owed to yourself, the common case — the one thing Reminder could express that Promise couldn't) and **`due_is_default`** (true when NOBODY chose the deadline — `set_reminder` defaults an omitted due to today's local EOD purely so the row lands on the dashboard's short-term/longer-term split). Lifecycle `active → kept|broken`; `auto_mark_overdue` sweeps once-cadence only (recurring never auto-breaks on a date) **and skips `due_is_default` rows** — breaking a deadline Gooni invented would mark Daniel broken at midnight every night on a commitment he never made. Chat-side closure via `find_active_match` (substring → unique-word-overlap → cosine ≥ **`CLOSE_MATCH_THRESHOLD` = 0.85**; top-2-within-`AMBIGUITY_GAP` 0.05 → ambiguity refusal → "which one?" ack). **That bar shipped at 0.60 and was raised 2026-08-15**: on `text-embedding-3-small` 0.60 is the *loosely related* band, not the paraphrase band, so "went to the store" could auto-close "go to the gym" — a lifecycle flip the router makes BEFORE the model sees the turn, with `patchPromiseState` having no UI caller, i.e. no undo. 0.85 is deliberately the same "this is the same commitment" bar create-dedup already uses (closure and dedup ask the identical question from opposite ends). Tiers 1–2 are untouched, so terse referents still close instantly; what changed is only the paraphrase tier. A single hit in the near-miss band **[`LOOSE_MATCH_THRESHOLD` 0.60, 0.85)** is returned as ONE candidate flagged `near_miss` and rendered as a question (`close "X"? not certain enough to do it myself`) — never acted on, and never reported as "no match", which would hide a real referent. `resolve_parent_hint` passes `threshold=LOOSE_MATCH_THRESHOLD` explicitly: a parent hint only ADDS a link, so a wrong guess is cheap and editable, unlike closure. Net: `tests/test_promise_match_threshold.py`. CREATES from chat do NOT auto-insert — see glow below. `DELETE /promises/{id}` hard-deletes (undo path).
- `Trackable` + `TrackableEntry` — generic measurement (Notion-tables model). Definition: `name` (lowercase-unique), `kind` (`boolean|numeric|json`), `agg` (`sum|last` per-day fold), `unit`, `cadence`, `target`, `is_important`, `schema_hint` (JSON hint incl. optional `direction: limit|floor`), `source` (`manual|chat|whoop|leetcode|shortcuts|derived|focus_cam`), `parent_promise_id`. Entry: sparse `value_boolean|value_numeric|value_json` + `(trackable_id, date)` index; multiple rows/day legal. New tracked thing = one INSERT. 8 system trackables (calories/protein sum-agg; weight/exercise/note + three personal habit flags, last-agg) + feed masters (`whoop`, `leetcode` json) + numeric mirrors. **Shortcuts events** (`source=shortcuts`): an iOS Shortcuts automation (App Opened, Arrive/Leave a location, CarPlay, charger, NFC…) POSTs `{subject, event, at?}` to `/events`; each ping is +1 on a per-`"{subject} {event}"` sum-agg numeric Trackable created on the fly (`event_service.log_event`), with the clock time stored in `value_json.at` (the seam for future arrive+leave dwell/session math). No hardcoded event vocab — a new trigger needs ZERO backend change. No Apple Screen Time API (needs the paid FamilyControls entitlement), no session pairing yet (counts only). Appears in the **expanded log matrix** (`LogTable`'s `isDaily` keeps them) + the activity rail as "device" events, but is EXCLUDED from the **compact daily-dots glance** (`LogDots`'s `isDaily` drops `source=shortcuts`) — device telemetry is ambient, not priority, and a handful of triggers crowd the single-row glance and bury the OG trackables. The compact glance stays priority-only (system + manual); NOT the special whoop/leetcode feed tiles. **Focus-cam** (`source=focus_cam`): the local webcam focus sidecar's data (see the Focus-cam section) is WALLED off from EVERY existing trackable surface — `trackable_service.HIDDEN_SOURCES` drops it from `list_all` (so `/trackables` matrix/dots + overlay + chat `read_trackable` never see it) and `activity_service._trackables` filters it from the rail; read ONLY via `/focus/cam/*`. Stronger than the `shortcuts` client-drop (enforced at the query, no client can surface it). **24hr Fitness sync** (`app/services/fitness_24hr.py`): reverse-engineered personal-interop pull — logs into 24hourfitness.com (captcha not backend-enforced → `captchaToken:null`), reads the day's club check-ins, and if any AND the `exercise` cell is empty, writes `exercise="gym"` in-process via `daily_metric_service.set_cell`. Idempotent + never clobbers a manual push/legs label. Runs SERVER-SIDE from the hourly `_integration_refresh_loop` in `app/background.py` — NOT a cron: the one periodic job that also refreshes whoop + leetcode (each sub-refresh independently guarded, off the event loop via `asyncio.to_thread`). Fills the log even on days the app is never opened. Secrets = fly secrets `TFHF_USERNAME/TFHF_PASSWORD` (in-process write → no bearer). `scripts/sync_24hr_fitness.py` = manual/debug CLI over `sync_today`. Setup: `scripts/README_tfhf_sync.md`.
- `Message` — the log substrate. Slice 3 glow cols: `has_actionable_signal` (sticky extractor verdict) + `signal_preview` (JSON `{signals, status: pending|promoted|dismissed, promise_ids}`). `GET /messages/log` = flat newest-first stream across all conversations w/ source badge. **`GET /messages/glowing`** = the still-PENDING glows only, newest first — the ambient home's limbo lane read, deliberately NOT a slice of the log (recency of chatter is not the question; `signal_preview` is JSON text so the SQL `LIKE` is only a prefilter and the parse is authoritative, and a flagged row with a null preview counts as pending). It answers **`{items, total}`**, and the parse runs over EVERY candidate rather than over the page: `total` is what the lane's `+N more waiting` line reports, so a count bounded by `limit` would be a capped claim presented as complete (the no-silent-caps rule), and applying `limit` before the parse could under-fill a page — a prefilter false positive spends a slot while a genuinely pending row sits past the cut. Rows and total come from ONE list under one predicate (`_preview_is_pending`) and cannot disagree. `POST /messages/{id}/promote` (runs `promise_service.create_from_signal` per draft), `/undo-promote` (hard-deletes exactly those promises, restores pending), `/dismiss-glow`. `GET /messages/{id}/trace` = full per-turn audit bundle (orchestrator step trace off `Message.trace` + `ToolCall` audit rows by message_id + paired user utterance + post-turn `Reflection`); assembles data that already existed keyed to the assistant message — powers the recent-chat ribbon's audit panel.
- `Edge` — semantic graph (`utters`, `derives_from`, …). UNIQUE on the 5-tuple; promise deletion clears its edges.
- `Memory` — KEPT (Daniel's override). Reconcile dance + cosine retrieval + MCP tools unchanged; the capability prompt block is gone (OBJECT_KINDS is the remaining anti-hallucination anchor). **Provenance (migration `c7e9a1f4b2d8`, 2026-07-12):** `source_message_id` (nullable FK → messages.id) is the chat twin of `source_note_id` — set to the user-utterance id in `_apply_add`, threaded from `orchestrator/core.py` (both reconcile trigger sites pass `user_msg.id` into the daemon `apply_memory_candidates` thread; the note path rides `RouterContext.source_message_id`). `GET /memories` resolves either id into a displayable `source` object (`_attach_sources` = 2 batch queries: Message preview + Conversation channel, or Note title); `null` for pre-provenance chat memories + injected prefs. `/memories` row surfaces it via `SourceTrace` (note → opens note; chat → reveals the source utterance inline). Forward-only — old memories stay null (unbackfillable).

**Infra kept:** `Conversation`, `ToolCall` (audit), `WaProcessedId`, `Attachment` (note-owned only now), `Reflection` (deterministic guards; facet promotion removed), `PublicProfile`, `Visit`, `OAuthToken`, `Settings`, `EvalSegment`/`EvalStepFeedback`/`EvalMessageRating`, `Trackable(Entry)`.

## Architecture

### Backend (`app/`)

- **`app/main.py`** — SLIM wiring: middlewares (auth Bearer, CORS, req-trace, visit-log), `_lifespan` (eval pending backfill, fly-revive, then background loops), `_alembic_upgrade`. **Background loops in `app/background.py`**: note-excerpt backfill + memory watchdog + `_integration_refresh_loop` (hourly whoop/leetcode/24hr-fitness refresh, data-pull not proactiveness) + **`_proactive_loop`** (the one loop that can SPEAK unprompted — see the PROACTIVENESS section below; its blocking tick goes off the event loop via `asyncio.to_thread`, same as the refresh loop, because no request may wait on background inference). The old nudge scheduler + proactive tick stay dead. Routers never import from `main`.
- **`app/db/models.py`** — see Core data model above.
- **`app/common.py`** — date parsers + auth-token + `local_now(db)`/`local_today(db)` (canonical tz-aware "today" in `Settings.nudge_tz` — legacy column name, the tz survived the nudge nuke; NEVER `date.today()` — server runs UTC) + `parse_due_hint(hint, db)` — THE one deadline parser (regex map + dateparser fallback, local-EOD anchored). `promise_service._infer_due_from_text` scans utterances and delegates here; never grow a second resolver.
- **`app/services/embedding_utils.py`** — `embed_text` + `cosine`, THE shared embedding surface (extracted from dead list_service). All cosine matchers (promises, memory, feature dedup) go through it.
- **`app/services/memory_service.py`** — unchanged reconcile/retrieval core. Retrieval = always-included prefs + top-5 cosine (no capability block anymore). `MIN_QUERY_LEN` read gate stays tiny.
- **`app/services/memory_extraction/`** — single LLM call per turn (`extract_signals`, gpt-5.4-mini, max_tokens=1500) emits `tone_corrections`, `feature_requests`, **`promises`** (unified emit: kind=`create|complete|break`; create carries utterance/summary/cadence/cadence_target/due_date (absolute, clamped today..+366d)/due_hint/is_important/parent_hint; recurring cadences are stripped of due dates — a due on a daily promise is a parse artifact), `reply_intent`, memory candidates. (Fitness/`fitness_logs` extraction was REMOVED — the calorie-guessing auto-writer was Claude-competitive NLP; trackable logging is now the explicit `log_trackable_entry` tool. `_normalize_fitness` + `_MACRO_ESTIMATE_PROMPT` gone.) Prefilter gates note-saves only.
- **`app/services/intent_router.py`** + **`intent_handlers/`** — single dispatch. Handlers: `memories`, `features` (→ `feature-request`-tagged Note via `create_feature_request_note`, tiered dedup; the import is MODULE-LEVEL so a broken handler fails `tests/test_imports.py` at boot instead of hiding behind the router's per-handler `except` — it imported a non-existent name and silently dropped every feature request until 2026-08-11), `tones`, `promises` (create → GLOW annotation on the source Message + `RouterResult.noticed_promises`; complete/break → auto-transition). (The `fitness` handler was DELETED with the fitness-intent pipeline — trackable writes are now the `log_trackable_entry` tool, not router-captured.) `RouterResult`: `captured_promises/noticed_promises/completed_promises/broken_promises/failed_promise_actions/captured_features/tone_rules/reply_intent`.
- **`app/services/promise_service.py`** — create (dedup ≥0.85, slip ≥0.80, utters edge), `create_from_signal` (due resolution + parent hint — shared by promote route), `find_active_match` (auto-close bar `CLOSE_MATCH_THRESHOLD`=0.85, near-miss/loose floor `LOOSE_MATCH_THRESHOLD`=0.60 — the bar is a keyword-only PARAM, not a module read, because closure ACTS and parent-hint linking only LINKS), `resolve_parent_hint`, `transition`, `delete` (row + edges), `auto_mark_overdue` (once-cadence only), `update` (text/due/importance/cadence).
- **`app/services/promise_evaluator.py`** — deterministic voice-of-reason checks (unchanged; conflicts-active band 0.72).
- **`app/services/trackable_service.py`** — generic CRUD + `log_entry` (append / `replace=True` cell-collapse) + `day_value`/`pivot`.
- **`app/services/daily_metric_service.py`** — fitness-semantics ADAPTER over Trackable rows (legacy signatures + response shapes: `log`, `running_total_for_today`, `today_food_ledger`, `update_most_recent`, `set_cell`, `cut_table`, `list_entries`). `/metrics/*` routes ride on it; CutTable FE contract unchanged.
- **`app/services/overlay_service.py`** + **`routers/overlay.py`** — `GET /overlay`: 4 deterministic zones w/ `reason` strings (action_horizon: overdue → due ≤48h → important; trackables_today: met/missed/logged/pending, direction from schema_hint else protein=floor/limit; anchor note; whoop_select from `Settings.overlay_whoop_keys`). **It has a SECOND consumer since 2026-08-15: the chat prompt** (`prompt_blocks._build_overlay_block`) — see below. The route stays the only writer of the rules; the prompt block renders and never re-derives.
- **`prompt_blocks._build_overlay_block(db)` — the ranked horizon reaches the model (2026-08-15).** Until this, the prompt carried an UNRANKED promise dump (`_build_state_block`) and **zero** trackable-target awareness, so "what should I focus on?" was answered from vibes and "how am I doing on calories?" cost a tool call or a shrug. The block renders `overlay_service.build_overlay`'s output — top `OVERLAY_HORIZON_CAP` (4) horizon rows with their `reason` turned into a phrase (`overdue by 2d` / `due in 5h` / `flagged important`), today's met·missed·in-progress·not-logged fold with the numbers for every targeted trackable (the `reason` string IS `"2400 vs limit 2100"`, so the value is not rendered twice), and the Promise Integrity Score. ~180 tokens at full caps. Four rules: **injected on EVERY source** (web included — web has UI showing these rows, but the MODEL cannot see UI; #482 moved `state_block`/`time_block` off the `if source != "web"` gate for the same reason, so the only block still behind it is bot DELIVERY mechanics. `tests/test_overlay_prompt_block.py` pins this by indentation plus a no-gate-between check, since calling `_assemble_context` for real would drag memory recall onto the network); **no second cascade** — a wrong ranking is fixed in `overlay_service`, and the PIS line CALLS `routers.promises.promise_integrity_score(db=db)` rather than restating the kept +1.0 / broken −1.5 weighting (a lazy import, so no cycle; the route is the owner); **no silent caps** — a cut horizon says `+N more`, a cut trackable list says so, because a truncated list read as the whole list is how "that's everything, sir" becomes a lie; and **a `due_is_default` row ranked overdue is tagged `(auto-set date, not his deadline)`** — `overlay_service` doesn't know about the flag and ranks it overdue like any other, and without the tag the model scolds Daniel for missing a deadline GOONI invented, the same failure `auto_mark_overdue` avoids by skipping those rows. Deliberately NOT a nudge: the header tells the model to answer FROM it, not to volunteer it. It overlaps `state_block`'s promise lines — same rows, so the two can restate but never contradict; kept because `state_block` LISTS what's open and this one RANKS it and says why, and it is the only surface carrying today's trackable targets. `_cadence_tag` is shared by both so a promise reads identically in each.
- **`app/services/whoop.py`** — OAuth + client unchanged; storage = `whoop` json master Trackable + numeric mirrors, replace-mode per local day. `get_today`/`latest_snapshot` read back dicts. `subject_day(doc, db)` = the local day a reading is actually FOR (from `sleep_end_at` → `source_updated_at` → `updated_at`), so a day-old snapshot can be tagged stale. `/whoop/today` adds `day_label` (`''` when current, else `yesterday`/`Jul 14` via `common.stale_day_label`) — the tile shows an amber stale-tag; rest of the shape unchanged.
- **`app/services/gmail_service.py`** (2026-08-15, SCAFFOLD) — reuses the Calendar `OAuthToken` row (provider `google_calendar`), not a second OAuth client: `google_calendar.SCOPES` gained `gmail.readonly`, so the existing refresh dance covers both. **Captain TODO**: add that scope on the OAuth consent screen + reconnect via `/auth/google/start` once. `GET /gmail/threads` · `GET /gmail/threads/{id}` · `GET /gmail/search?q=` · `GET /gmail/status` (surfaces whether the granted scope actually includes `gmail.readonly`, since an un-reconnected token still "connects" but 403s on first call).

- **`app/services/leetcode_service.py`** — same pattern (`leetcode` master + mirrors, per UTC day).
- **`app/services/orchestrator/`** — `core.py` (persona v10: promise-first language, glow NOTICED-not-tracked guardrail, anti-hallucination now backs write-claims by [just extracted] id OR a successful write-tool call, and — v10, 2026-08-15 — **the blanket CAPTURE suppression is gone**. The "terse ack, add nothing" rule was written when the model was effectively blind on web (~13 tokens of dynamic state), so a bare `noted, sir` was the only honest reply it could give; it now sees promises + due dates, the food ledger, `[recent — last 1h]` and `[doing — last 30m]`, and the suppression was costing exactly the replies that context was built for. ## MCP surface — ONE module, three transports (CONVERGED 2026-08-10)

**Every tool is defined exactly once, in `app/mcp_surface/tools.py`.** Adding a tool = append to `ALL_TOOLS` + the transport list. Before this there were three surfaces: 25 stdio tools for Claude Code, and the same seven "focus" tools written out TWICE (in-process for the `/mcp` mount, over httpx in `focus_server.py`) — the duplication that produced #458's schema drift.

**The surface mirrors the DATA model, not the retired pre-#458 primitives.** A thought IS a Note tagged `thought`; a reminder IS a Promise with `owed_to`. So each table has ONE writer, and the readers collapse the same way:

**Notes** (6): `log_note(content, kind="note"|"thought", topic?, title?, tags?, new_batch?, label?, at?, is_draft=True, is_pinned?)` — absorbs `log_thought`+`add_note`, discriminated by `kind`; `kind="thought"` needs `topic` and rides the batch/salience path, `kind="note"` writes a titled document. `is_draft` DEFAULTS TRUE because that is what MCP-written notes always actually were (`POST /notes` defaults it on, so the old tool's `is_draft=False` was inert) — passing False now genuinely publishes · `search_notes(q?, kind?, tag?, topic?, since?, limit?, match="semantic"|"substring")` — absorbs `query_thoughts`+`list_notes`+`find_note`+`list_recent_notes`; `kind="thought"` always matches by substring (it's the recall check against Claude's own writes) · `read_note` (the ONLY full-body read; renders task lists as `[ ]`/`[x]`) · `edit_note` · `delete_note` · `attach_file_to_note`.
**Promises** (3): `set_promise(content, due?, owed_to?, cadence?, cadence_target?, from_thought?, is_important?)` — absorbs `set_reminder`+`add_promise`. The **inert `is_promise` param is GONE**. The two parents disagreed on one rule and the merge keeps the right one: a RECURRING cadence drops the today-EOD default due (a due on a daily promise is a parse artifact), while a `once` promise keeps it flagged `due_is_default` for dashboard placement · `list_promises(day?, state="active"|"kept"|"broken"|"all", limit?)` — absorbs `list_reminders`+`read_promises` · `set_promise_state(promise_id, state)` (renamed from `set_reminder_state`).
**Topics** (2): `list_topics`, `create_topic`. **Trackables** (3): `add_trackable`, `log_trackable_entry`, `read_trackable` (the generic reader — json-kind payloads come back whole, which is why `get_leetcode_activity` could go). **Memory** (6): `get_context`, `add_memory`, `search_memories`, `edit_memory`, `forget_memory`, `list_preferences`.

**20 tools total** (was 25 stdio + 7 focus with 7 implemented twice). **DELETED, captain-approved** — each verified first to lose no reachable data: `read_todos` (`search_notes`+`read_note` reach the same note), `check_task`/`claim_task`/`release_task` (`edit_note` writes the note HTML, and `read_note` renders the checkboxes), `get_leetcode_activity` (`read_trackable("leetcode")` returns the same `value_json`).

**The HTML-checklist task board is GONE with them** — there is no longer a `⏳ [agent | timestamp]` claim protocol, so nothing coordinates two agents working the same note (the old `claim_task` refused when another agent held an item and reported its staleness age). A checklist note is now just a note: read it, edit the HTML, write it back. Don't reinvent the marker convention on top of `edit_note` without a deliberate decision — a read-modify-write with no atomicity is worse than no protocol, because it looks like one. `.claude/skills/work-backlog`, the only consumer, was deleted in the same pass.

### The gateway seam (`app/mcp_surface/gateway.py`)

Two impls, one interface. **This is not optional plumbing:** the stdio server runs on Daniel's LAPTOP against PROD (`GOONI_URL=https://gooni-bot.fly.dev`, see `.mcp.json.example`), and prod's SQLite is on a Fly volume with no route from there — so calling the services directly would silently repoint every Claude Code write into a local DB file, writes that look successful and land where nothing reads them.

- `DirectGateway` — same process, session per operation, commits on success. Used by the `/mcp` mount.
- `HttpGateway` — Bearer-authed httpx (`GOONI_URL` + `GOONI_AUTH_PASSWORD` → sha256). Used by both standalone servers.

**The anti-drift rule: gateways do DATA ACCESS ONLY** — no coercion, no formatting. Where a tool needs two writes atomic (create-a-promise-then-set-its-cadence), the composite is ONE gateway method so it is one transaction on both sides. Recurrence routes through `PATCH /focus/reminders` + `focus_service.update_reminder` in BOTH impls, so responses are identical by construction rather than by agreement between two hand-written serializers. `focus_service._serialize_reminder` gained `cadence`/`cadence_target`/`is_important` for that reason (additive). `tests/test_mcp_surface.py` asserts gateway parity key-for-key.

### Three entry points, all registering off that module

- **`app/focus_mcp.py` — PROD (Fly), the primary path.** In-process FastMCP mounted at **`/mcp`**, `DirectGateway`, `REMOTE_TOOLS`. Deploying to Fly ships a stable always-on `https://gooni-bot.fly.dev/mcp` — no tunnel. Exempt from the Bearer middleware (authless by design — tools run in-process; the claude.ai dialog offers only OAuth, no static-bearer field). Wiring in `main.py`: `from . import focus_mcp`, `session_manager.run()` inside `_lifespan` via `AsyncExitStack`, `app.mount("/mcp", …)`, `/mcp` in the auth-exempt list. `stateless_http=True`; DNS-rebinding protection defaults OFF unless `FOCUS_MCP_ALLOWED_HOSTS` pins hosts. **All UNGUARDED on purpose** — these used to sit in bare `try/except`s that printed and continued, and the connector spent weeks 404ing on Fly while the app booted clean. A `/mcp` that can't mount now crashes boot. **No import shim:** the shadowing top-level `mcp/` dir is `mcp_servers/` now, so `from mcp.server.fastmcp import FastMCP` resolves to site-packages; `tests/test_imports.py` asserts the SDK resolves from OUTSIDE the repo.
- **`mcp_servers/server.py` — stdio, Claude Code.** `HttpGateway` (`mcp-stdio`), `STDIO_TOOLS`.
- **`mcp_servers/focus_server.py` — LOCAL DEV only.** Standalone streamable-HTTP on :8001, `HttpGateway` (`mcp-local`), `LOCAL_HTTP_TOOLS`; run as a script + a cloudflared tunnel for iteration before a Fly deploy exists.

Both standalone servers `sys.path.insert` the repo root so `app.mcp_surface` imports when run as a script (Python puts the *script's* dir on the path, not the repo root).

### Per-transport subsets + call logging

**A fourth, read-only consumer:** `GET /public/mcp` (the public resume page's MCP showcase) renders `STDIO_TOOLS` off `ALL_TOOLS` via `inspect.signature` + docstrings. It used to AST-walk `mcp_servers/server.py` for `@mcp.tool()` functions — which the convergence emptied — from `app/` rather than the repo root, so it returned `{"servers": [], "tools": []}` and the miss was swallowed. Servers come from `.mcp.json`, falling back to the committed `.mcp.json.example` (the real file is gitignored, so prod only ever has the template).

`REMOTE_TOOLS` / `STDIO_TOOLS` / `LOCAL_HTTP_TOOLS` are **declared tuples** at the bottom of `tools.py`, so "can claude.ai do X?" is read off one page instead of inferred. All three currently = the full set: the clients should be able to do the same things, steered by descriptions rather than by withholding tools. The mechanism stays because schemas cost context on EVERY claude.ai turn (why the remote surface was once cut to 7); at 20 tools that's affordable, and narrowing is a one-line edit. `register()` RAISES on an unknown name — a typo must fail at boot, not silently hide a tool.

**Every MCP invocation writes a `ToolCall` row** (`app/services/mcp_logging.py`, migration `e2b71c9f4a08` adds indexed `tool_calls.source`: `mcp-stdio`/`mcp-local`/`mcp-http`; NULL = the chat loop). `register()` applies it via a wrapper that copies `__signature__`/`__doc__` across — FastMCP builds the JSON schema by introspection, and a wrapper that dropped them would publish a tool taking `**kwargs` with no description. ## Focus system (2026-07-23) — CONVERGED into v2, 2026-08-08

The Claude-as-intelligence-layer pivot: **Claude** does extraction/intent/batching/query-formulation (via the Focus MCP connector, in-conversation); **Gooni** is pure persistence + a glanceable kiosk display; the display (not any agent) provides proactivity — an always-on screen showing what's due + which topics went stale needs no between-conversation machinery.

It originally shipped as a NEW primitive set alongside v2 so it wouldn't entangle the chat pipeline, with the overlap (Topic≈nuked Focus/Space, Thought≈Note, Reminder≈Promise) accepted on purpose.

**Why that ended (migration `f4c81a92de70`).** Claude reached Gooni through TWO connectors — claude.ai's `/mcp` wrote focus tables, Claude Code's stdio `mcp_servers/server.py` wrote v2 tables — and nothing linked them. Migration `d1a4c7f2b8e6` (2026-08-01) then COPIED every reminder into `promises` so the B4 dashboard could read them, and left both tables live: the connector kept writing `reminders` while B4 read `promises`, and the copies drifted. By 2026-08-08 all four prod reminders were verbatim promise twins — mark one kept and the other stood active forever. That copy also had to DROP what v2 couldn't hold: `owed_to` was folded into a `"owed to {name}: "` summary prefix, and every defaulted due was nulled (carrying it would have painted the promise overdue for a deadline nobody chose).

**The mapping now** — `focus_service` is an ADAPTER over v2, the same shape `daily_metric_service` has over Trackable. Every public signature and response shape is unchanged, so `routers/focus.py`, both MCP servers and every dashboard of the day needed no edits:

| focus | v2 | notes |
|---|---|---|
| `Thought` | Note, tag `thought` | `parent_note_id` → its batch; gains embeddings + `GET /notes/search` |
| `ThoughtBatch` | Note, tag `thought-batch` | `title` = Claude's label; `created_at`/`updated_at` = started/ended |
| `batch.image_url` | **Attachment** | note-owned already — no new column, and it lands on a real Note |
| `Reminder` | **Promise** + `owed_to` + `due_is_default` | `type` is now DERIVED (`owed_to is not None`) |
| `reminder.thought_id` | **Edge** `derives_from` | the graph layer already models (kind,id)→(kind,id) |
| `Mention` | dropped | 0 rows, no writer, no tool ever populated it |

**Survivors, and why.** **`Topic`** (`topics`) — a subject, self-FK `parent_id` for subtopics. `salience` float **bumped on write** (`+0.08` clamped to `[0.01,0.99]`), **decayed on read**: displayed = `salience × 0.5^(Δdays_since_last_touched / 7)`, floored `0.01`. No cron — decay is a pure function of `now` (like computing age from birthdate). `color` = per-topic identity (persisted, not meaning). It survived because synthesis can give you *which topic a note belongs to* but not stable identity across time (a re-cluster renames and re-splits; the dashboard flickers) nor a decay anchor (a curve needs a row's history). **`Person`** (`focus_people`) — survived because v2 has no person primitive at all; `Promise.owed_to` is its only consumer.

**Expand/contract.** `f4c81a92de70` is the EXPAND half: it backfilled every focus row into Notes/Promises and deliberately LEFT `thoughts`, `thought_batches`, `reminders`, `mentions` in place, unread. Reminders are matched to their twin by the `migrated_from_reminder` edge (exact) with a text-match fallback for rows written after 2026-08-01, and adopting a twin also RESTORES `owed_to` (stripping the summary prefix) and the defaulted due (`auto_mark_overdue` now honors `due_is_default`, so it's safe — and it puts those rows back on the short-term split instead of stranding them dateless).

**`b8f3d1c07a45` is the CONTRACT half (2026-08-09) — the four tables are DROPPED.** Only `topics` + `focus_people` remain of the focus schema. **Running `python scripts/verify_focus_convergence.py` against the target DB and getting a zero exit is a REQUIRED pre-deploy step, not a suggestion** — the drop is UNCONDITIONAL (there is no per-row refusal inside the migration), so the verifier is the only thing between a database with an unaccounted row and a lossy drop. It exits non-zero if any source row is unaccounted for, and short-circuits to 0 once the tables are gone. **The deploy is the irreversible step, not the merge** — `_alembic_upgrade()` runs at import time in `app/main.py`, so `alembic upgrade head` fires on uvicorn boot and shipping the revision IS the drop; there is no prompt in between. What makes that acceptable is that `upgrade()` **stamps provenance before dropping**: one edge per source row recording which v2 row absorbed it, keyed by the ORIGINAL id (`converged_from_thought_batch`/`converged_from_thought` → note, `converged_from_reminder` → promise). Those kinds are deliberately NOT `d1a4c7f2b8e6`'s `migrated_from_reminder` — that migration's `downgrade()` hard-deletes every promise reachable by its own kind on the premise it inserted them, so stamping it onto a promise this migration merely ADOPTED would make `alembic downgrade b6e4c2a9d713` destroy a user-visible row; the legacy kind is READ as the first-choice reminder matcher (exact provenance survives text drift) and never written. An in-migration refuse-to-drop guard was tried and deliberately removed: `promise_service.delete` wipes the promise *and* every edge touching it, so a reminder deleted through the dashboard legitimately has neither twin nor provenance, and a guard keying on that would refuse to boot forever over an action Daniel meant to take. `downgrade()` walks those edges backwards and rebuilds each row whose stamped v2 destination still exists AND can still satisfy the old schema, with its original id — which is the only way `thoughts.batch_id` and `reminders.thought_id` come back as real FKs instead of dangling integers. Rebuilt rows read the CURRENT v2 state, so connector edits made after the drop survive a rollback. **A rollback can be PARTIAL**: `thought-batch` notes are browsable (`_BROWSE_HIDDEN_TAG`'s `"thought"` LIKE pattern doesn't match `"thought-batch"`) and `delete_note` does no Edge cleanup, so deleting one strands that batch — and every thought under it, `thoughts.batch_id` being NOT NULL. Skipped rows are logged at WARNING per row plus a closing tally; the downgrade does NOT raise, since stopping a rollback halfway is worse than finishing it short. Like the expand half, downgrade LEAVES the Notes/Promises alone (deleting user-visible rows on a rollback is worse than a temporary duplicate pair — and that pair is exactly the state prod sat in for a week). `mentions` is dropped outright on the "0 rows, no writer ever" claim, but the claim is ASSERTED: `upgrade()` raises rather than destroying rows if the table isn't empty. Net: `tests/test_focus_convergence.py` (expand → contract → downgrade round trip → adapter, plus a downgrade chain through `d1a4c7f2b8e6` that must leave adopted promises standing — all on the real alembic chain).

**Session state is a persisted CLIENT store** (`stores/useFocusSessionStore.ts`, plain localStorage + a `storage` listener). No session table and no migration: `FocusSession` was retired into `TrackableEntry` on purpose and the only durable artifact a session produces is the entry it writes on stop. localStorage is what makes `/` and `/focus` agree across navigation, reload, and a second tab on another monitor, with no server round-trip per tick. It records SEGMENTS, not one stopwatch — the brief's `started-at + accumulated ms` totals correctly but can't answer "how much of this landed on which calendar day" once a pause splits the window, and a session crossing midnight has to write one entry per day. Each segment carries its mode; **break time is real elapsed time but it is not focus**, so only focus segments are ever written. Two rules make the totals honest. (1) **An open run is CAPPED at `MAX_RUN_MS` (6h) and the capped segment is flagged `truncated`** — mirroring the browser sensor, which closes a salvaged interval at its last confirmed heartbeat, marks it truncated, and hard-clamps at the same 6h its ingest rejects past (`interval_ingest.MAX_INTERVAL_SEC`); a focus session has no heartbeat, so the clamp is all there is. Without it the feature's most common failure — a session left running overnight — credits ~9h of sleep as focus against a Promise, which makes its primary output wrong. `sealedSegments(s, now)` is the pure closer both the write path and the corner stat go through, so the number on screen is the number that would be written. (2) **Write, then clear**: `seal()` closes the open run and PAUSES, `stop()` drops the session, and **`focusTime.ts::endFocusSession` is the ONE path that sequences them** — it calls the second only once `writeFocusSession` has resolved and otherwise THROWS, leaving a paused, retryable session instead of destroying the only durable artifact the session produces. It has two callers by design: `/focus`'s stop control (which reports the failure and stays put) and **`switchFocusSession`**, since the focus control is live on EVERY task row — starting focus on another task (or the running one) ends the current session first, silently, but only if its entry landed. `start()` on its own replaces the whole store key, so a switch that skipped this would delete unwritten minutes with no prompt; the switch is therefore CONDITIONAL, and a failed write aborts it with the old session intact. `endFocusSession` also holds its in-flight promise so a CONCURRENT caller joins it: `seal()` pauses without clearing, so between the seal and the write landing a second call would find the same session, seal identical segments and post the day again — doubling it on a sum-agg trackable. Nothing on screen changes until the write resolves, which makes a double-click the ordinary way to reach that. **`isAccruingFocus(session)` is THE one answer to "is focus accruing right now"** (`running && mode === "focus"`), and every consumer that starts or stops something on the session's liveness reads it rather than `running` alone — `running` stays true through a break, which is how the camera kept sensing and the row kept claiming to tick. Its consumers: the focus-cam control, the home's 1s-vs-60s tick cadence, and the TODAY row's indicator. (The ring's own `mm:ss` on `/focus` deliberately still ticks on `running` — it is the current MODE's stopwatch, so a break counting up is correct there.) The TODAY row's session indicator is derived ONCE from mode + running (`sessionRow`: `focus` | `break` | `paused`), because the row has THREE states and only one of them accrues: a pulsing dot and a ticking clock both claim time is accruing, break segments are dropped by `splitSegmentsByDay` (so `focused today` never moves and no entry is ever written for them), and a paused session accrues nothing at all. Break and paused name themselves and still route back to `/focus`. That reachable retry is why the session also carries **`writtenDates`**: the write is one `logTrackable` per calendar day on a **sum-agg** trackable, so a retry after a PARTIAL success would add the first day's minutes twice, and `replace` cannot be the fix (it would collapse the day and destroy every other session logged on it — trap 1). `writeFocusSession` skips days already in that list and calls back per landed day, so the record survives a reload too. `session.kept` also lives here rather than in either surface's local state, since `/` must keep showing a task marked kept on `/focus` struck through *and* running, possibly across a reload.

**Focus time — one Trackable, attribution on the ENTRY** (`services/focusTime.ts`). Get-or-create by name: **`focus`**, `numeric`, `minutes`, **`agg=sum`**, `source=derived`, `parent_promise_id` **NULL**. That null is the whole design: `Trackable.parent_promise_id` binds a definition to exactly one Promise, so a trackable per task would grow the log matrix a column per task and destroy it. The promise id therefore rides on `TrackableEntry.value_json` (`{promise_id, title, started_at, ended_at, segments}` plus `truncated: true` on the rows a CAPPED run fed — present only when true, so a capped session stays distinguishable from a genuine one with no migration and no new column; `source="focus"`), which the entry docstring already blesses — several rows per (trackable, date) are legal and the pivot folds them per `agg`. Three traps: (1) **never pass `replace`** — it collapses the day to the last session, the same way it collapses a boolean label write; (2) a session spanning midnight writes **two entries**, one per LOCAL calendar day, or the daily fold lies about both; (3) `value_json` is unindexed Text and the only index is `(trackable_id, date)`, so per-task totals are a read of this one trackable's entries grouped in code — fine at this volume, do NOT add an index or a column to avoid it. **The entry is also the SESSION WINDOW OF RECORD** (2026-08-15): `segments` carries the EXACT focus runs, midnight-clipped and sorted, because the backend's attribution layer overlaps device intervals against them and `started_at`/`ended_at` are only the day's ENVELOPE — every run on a day folds into one entry, so an envelope spans any pause and would credit the Promise with the lunch scroll. See the Focus attribution section. The column is **VISIBLE but READ-ONLY in the log matrix** (`focusTime.ts::isReadOnlyRollup`, honoured by `LogTable`'s numeric edit / cell clear / boolean toggle / boolean tag and by `LogDots`' equivalents): every matrix verb carries `replace: true`, which DELETEs the whole (trackable, day) before inserting — on this column that destroys each session row's `value_json` (promise id, window, `truncated`), which no cell edit could reconstruct. The sessions are the source of truth and the cell is only their sum, so hand-editing it was never meaningful. The predicate is deliberately NOT every `source="derived"` trackable: the whoop and leetcode numeric mirrors share that source and stay editable. Those read-only cells render through `fmtMinutes` (`25m`, not the stored `24.98` a click-stopped stopwatch actually writes) — rounding at the RENDER boundary, since the fractional value is the honest sum and the per-task math reads it; ordinary numeric columns still show their raw value. Consequences: per-task accrued time on the TODAY rows, and `focused today` in the corner (the single rollup that crosses into the log matrix) — which folds the LIVE session through the same `splitSegmentsByDay` and keeps only today's draft, so a session that began yesterday can't add yesterday's minutes to today's stat. That fold needs a LIVE clock even while the session is PAUSED (a 60s tick, vs 1s while running): the day key comes off the tick, and a tick frozen at the pause keeps answering "yesterday" past midnight — reintroducing the very error the fold prevents. Net: `frontend/src/services/focusTime.test.ts`.

That flag is load-bearing, not bookkeeping: `auto_break_overdue` skips defaulted dues, because breaking them would mark Daniel broken at midnight every night on a deadline GOONI invented. A stale defaulted due rolls forward to `today`; an explicit one that passed reads `overdue`. `_due_bucket` compares in LOCAL time — an EOD-anchored due stores as 06:59 the NEXT UTC day, so raw UTC date math files every "today" under "tomorrow". ## Browser sensor (2026-08-08 — Chrome extension, ADDITIVE)

A Manifest V3 Chrome extension (`extension/`, unpacked dev-mode, no build step,
no deps) records **which tab actually held focus and for how long**, buffers
locally, and batch-POSTs to Gooni. It closes the one sensor gap: GitHub, Whoop,
Calendar, iOS Shortcuts and focus-cam all feed Gooni; the browser did not. The
motivating question is "when I say I'm doing X, am I actually on it?" — the URL
is the task identity and tab-focus duration is the timer.

- **Extension internals** (README + rationale: `extension/README.md`). `src/background.js` is the ONLY chrome-touching file — everything with logic lives in chrome-free modules so it is unit-testable: `tracker.js` (the interval state machine), `buffer.js` (chrome.storage.local buffer + flush/retry), `scrub.js` (the privacy model), `attention.js` (the idle-aware "is the human here, and on what?" decision), `serial.js` (the write queue), `status.js` (the options page's last-flush report), `format.js` (the popup's display formatting), `config.js`. Tests: `cd extension && npm test` (node:test, zero deps). **Every storage mutation goes through ONE promise-chain queue** (`serial.js`, held in `background.js`): chrome dispatches listeners back-to-back without awaiting them, so the `onActivated`+`onUpdated` pair one tab switch delivers would otherwise interleave, both read the same open interval and both close it into two `client_id`s — an overcount the server can't dedup because the ids differ by construction. The queue only orders work within one worker generation; all real state is in `chrome.storage.local`, so an MV3 teardown mid-queue restarts clean with no lock to leak. `_`-prefixed internals are the unserialized bodies (safe to call each other inside the critical section); their public wrappers are the only thing listeners may call. Three honesty rules are load-bearing: **idle is backdated** (chrome.idle reports after 60s of no input, so the interval closes at `now − 60s`) **and idle is part of the attention decision itself, not a separate event path** — `attention.js::resolveAttention` probes `chrome.idle.queryState` FIRST and treats anything but `active` as no attention, because a focused Chrome window is not an attending human (walking away never unfocuses it, so `getLastFocused().focused` stays true through a two-hour lunch and the 30s heartbeat would re-open the interval chrome.idle had just closed, crediting the whole idle stretch as focus). One decision, every caller inherits it; the heartbeat consequently doubles as a second idle detector when the worker slept through `onStateChanged`. The probe fails CLOSED (throw, junk answer, or no answer within 2s → `idle`) and always settles — it runs inside the serialized reconcile slot, so a pending callback would wedge every later event; **a poll-discovered blur closes at the last CONFIRMED heartbeat**, never at discovery time (macOS never fires `windows.onFocusChanged` when another app takes the foreground — verified on Chrome 151 — so the 30s heartbeat is the real detector, and the residual error is always an undercount); **a salvaged interval is flagged** `truncated` and closed at its last heartbeat, so a browser killed overnight can't report a 16-hour session. Both boot paths (`onInstalled`/`onStartup`) salvage BEFORE reconciling, since `now` at boot proves nothing about the past.
- **Privacy: full URL for every host, credentials scrubbed.** Hostname-only was rejected — it destroys both the "what distracted me" question and the LeetCode path identity (`/problems/<slug>/`). Query params whose NAME carries a credential SEGMENT are value-replaced with `REDACTED` before the interval is ever buffered; the fragment is dropped whole (implicit-flow OAuth returns `#access_token=`). **The matcher is THREE checks, redact if ANY fires** — arrived at because each simpler design failed in one direction, and both directions are real harm (over-redaction destroys the value pre-buffer and is unrecoverable; under-redaction stores a live credential): **(1) squashed whole-name** (lowercase, delete `_`/`-`, compare to a set of glued credential names — `jsessionid`, `accesstoken`, `xapikey` … `SCRUB_SQUASHED_NAMES`/`SCRUB_PARAM_SQUASHED_NAMES` are the lists; entries are stored pre-squashed since that's what they're compared against) — the only check that catches a name with no boundary to split on, and what keeps the `api_key`/`x-api-key` family covered once `key` stops being a segment; **(2) whole-name only** (`code`/`key`/`state`, the bare OAuth params) — deliberately NOT segments, where they ate `zip_code`/`country-code`/`error_code`/`sort_key`/`us_state`/`page_state`; **(3) segment** (lowercase, split on `_`, `-`, **camelCase** and digit boundaries, any piece in the credential set). Substring matching was the first cut and it ate real params (`auth`→`author`/`authors`, `sig`→`assignee`/`design`/`designer`/`insight`); pure `_`/`-` segments then leaked every camelCase name (`accessToken`/`idToken`/`sessionId`/`clientSecret` stored a live bearer token verbatim) — the camelCase split is what closed that. Only the SEGMENT list is editable from the options page with no rebuild (a saved list REPLACES the default; checks 1–2 are structural and can't be edited away); defaults in `extension/src/scrub.js` (`SCRUB_SEGMENTS`/`SCRUB_WHOLE_NAMES`/`SCRUB_SQUASHED_NAMES`), mirrored by the fixed server-side floor `browser_activity_service.scrub_url` — SAME three checks over the SAME three sets, deliberately NOT user-editable, since a floor a hostile client can turn off is decoration. Both sides are pinned by the same literal KEPT/REDACTED table in the same order (`extension/tests/scrub.test.js` + `tests/test_browser_intervals.py`) so they can't drift. The floor runs over BOTH `url` and `path` through that one function — the extension only ever sends `pathname`, but the floor exists for the clients that AREN'T the extension, and one posting `/callback?code=…` in `path` would otherwise get under it. It also strips **HTTP-basic userinfo** (`alice:hunter2@host` → `REDACTED@host`, host/port/IPv6-brackets preserved exactly): a stronger credential than an OAuth code, and it used to slip through twice over — the no-query/no-fragment early return returned the URL verbatim, and `urlunsplit` re-emitted `netloc` untouched when it didn't. `chrome://`/`file://`/extension pages are never recorded.
- **`app/db/models.py::BrowserInterval`** (`browser_intervals`, migration `c4d7e9a1b306`) — host/path/url/title, naive-UTC `started_at`/`ended_at`, server-computed `duration_sec`, `end_reason`, `truncated`. `client_id` UNIQUE is the idempotency boundary (the WaProcessedId.wamid pattern): the extension mints it at interval close and it survives every retry, so a redelivered batch dedups instead of double-counting attention.
- **`app/services/browser_activity_service.py` + `app/routers/browser_activity.py`** — `POST /browser/intervals` (batch, ≤500; returns `{accepted, duplicates, rejected:[{client_id,reason}]}` — one malformed row must not cost the extension its whole buffer) and `GET /browser/intervals?day=&limit=` (verification read, no UI). Bearer-authed by the global middleware, same as the Shortcuts `/events` ingest. The ingest mechanics themselves — recomputed durations, the reject-don't-clamp validation limits, the `client_id` idempotency boundary and the per-row SAVEPOINT — are **`interval_ingest.py`**'s since the desktop sensor landed; see the Device rows section.
- **Delivery is retain-by-default.** The extension drops a batch ONLY on `400`/`413`/`422` (a body refused identically forever, so retrying wedges the buffer behind one poison batch). `429` (Gooni's own 300/min rate limiter, which stored nothing) and `404` (a `baseUrl` on the wrong host/dev port) retain like `5xx`/`401`, and a `Retry-After` header is honoured, capped at 15min. The flush itself is bounded by `FLUSH_TIMEOUT_MS` (20s, abort + race, retryable like offline) for the same reason `attention.js` bounds its idle probe: both run in the ONE-slot serial queue, so a server that accepts the connection and then goes quiet would hold the slot and stall every later tab switch, blur and heartbeat — a silently dead sensor with nothing erroring. A permanently-wrong `baseUrl` still can't grow the buffer unbounded — `MAX_BUFFERED` drops the oldest and COUNTS the loss. **Two durable loss counters, deliberately distinct**: `DROPPED_KEY` = buffer overflow, `REFUSED_KEY` = destroyed because the server refused the batch (`discardRefused`, not `ack` — ack means "the server has it"). Folding the second into the first would swap one wrong number for another, since the options page labels `dropped:` as overflow-only. A server-REJECTED row was acked and deleted like an accepted one, so the options panel (`status.js::formatLastFlush`) is the only place that loss is visible: it prints the rejected count + first reason, a separate `destroyed N` for a refused batch (a bare `error http_413` read like something to retry), and marks an all-rejected batch distinctly, since the reachable no-bug case (a clock >5min fast → every row rejected as `future`) otherwise reads as a healthy flush forever. Both counters live in `chrome.storage.local`, so they survive the next flush overwriting `gooni_last_flush`.
- **`GET /browser/intervals/summary?days=N` (or `?start=&end=`) — the popup's ONLY read, folded in SQL.** `browser_activity_service.summarize` issues exactly two grouped queries per period (`GROUP BY host`, and a `GROUP BY` over a per-day CASE ladder) and returns `{start, end, days[], hosts[], totals}`, each carrying `total_sec`/`sessions`/`truncated_sec`/`truncated_sessions`. Nothing downloads raw rows: a tab-focus sensor writes thousands a week, and summing them client-side gets visibly slow within a month and never gets better. Day buckets are LOCAL days computed as tz-aware midnights **per day**, not one fixed UTC offset — a DST switch inside a 7-day window would otherwise misfile an hour on either side of midnight (same class as `test_focus_due_bucket`). An interval crossing midnight is attributed WHOLLY to its start day (intervals close on every switch/blur/idle, so a surviving span is rare and short, and a split total can't be reconciled against the session count beside it). Window capped at `MAX_SUMMARY_DAYS` (31) so the CASE ladder is bounded. Net: `tests/test_browser_summary.py`.
- **The popup (`extension/popup.html`/`popup.js` + `src/format.js`)** — the toolbar `action`, added alongside the existing `options_page` (config and glance are different jobs). Headline total for today / last 7 days, a 7-day trend chart, ranked per-host rows (favicon · domain · `1:13:10` · bar · share · session count). READ-ONLY: it touches nothing in the sensing path beyond the existing `gooni:status` message, which it uses for the buffered count. Its honesty rules are the reason it exists in this shape: **truncated rows are counted AND marked** (hatched share of the trend bar, `⚑` on the row, a line stating how much of the period is a floor rather than a measurement — dropping them understates the day, showing them silently overstates it); **buffered intervals are named** with "totals exclude them", so a low number isn't read as a quiet day; **empty reads as empty** — no rows gives "No data yet" and an em-dash headline, never `0s`, and a FAILED fetch says so rather than falling back to zeros (`0s` is a claim about the day and an unreachable server is not evidence for it). `favicon` permission = chrome's own cache, never a third-party favicon service (that would ship every visited host to someone else — exactly what the privacy model exists to prevent); no icon → letter chip. Formatting is chrome-free in `src/format.js` (`extension/tests/format.test.js`), same split as `status.js`.
- **Delivery failure is now VISIBLE (2026-08-12).** The retain-by-default rules above never LOSE data; what they couldn't say is that data had stopped ARRIVING, and every failure mode was invisible unless you opened the options page. Two fixes. (1) **`DEFAULT_BASE_URL` is `https://gooni-bot.fly.dev`, not `http://localhost:8000`** — a fresh install used to buffer against a backend that only exists while `dev.sh` runs, and looked healthy doing it. Defaulting-to-deployed was chosen over refuse-until-configured for the same reason `enabled` defaults ON: an installed sensor that senses nothing is worse than no sensor, and refusing records nothing until someone visits options — the same lost data with a better excuse. A wrong-but-reachable default costs nothing either, since everything is buffered until the server confirms it. (2) **`extension/src/health.js` → a toolbar badge + popup banner.** Computed from CONFIG + BUFFER, deliberately NOT from `gooni_last_flush`, because the worst states never write one: with no token `flushOnce` returns `not_configured` with `sent:0` and `recordFlush` skips zero-sent flushes, so `lastFlush` stays null FOREVER while the buffer grows. Ladder: no token / rejected token / failing-with-backlog(≥25) = red `!`; one failed send or past loss (`refused`/`dropped`) = amber; `retry_after` backpressure and healthy = SILENT (a permanent badge is one you stop reading); paused = grey `‖`, never rendered as broken. A live outage outranks historical loss. Net: `extension/tests/health.test.js`.
- **The extension also owns the NEW TAB (2026-08-13).** `chrome_url_overrides.newtab` → `extension/newtab.html`, which frames the deployed frontend full-bleed (`allow="microphone; autoplay; clipboard-write"` — voice-first needs an explicit grant, a cross-origin iframe gets no mic otherwise). NOT bundled: bundling forces a build step onto a deliberately buildless extension and MV3 bans remote code there, whereas framing keeps the app on ITS OWN origin, so its token, its prefs and its backend calls are a normal tab's and **no backend change is needed — the CORS allowlist is untouched**. The frontend URL is its own config key (`gooni_app_url`, `DEFAULT_APP_URL`, options-page field), separate from `baseUrl` because the app and the API are different hosts. Failure is never a blank tab: the reachability probe runs ALONGSIDE the frame load, not after it, because Chrome fires the iframe's `load` event for its own "refused to connect" page exactly as it does for the app. `IFRAME_ALLOW` lives in `src/newtab.js` and is applied by `newtab.js` BEFORE `src` is assigned (`allow` is read at navigation) rather than written as an HTML attribute — one owner, so the test guarding voice guards the value the page uses. The reachability probe and the frame-blocking header check are ONE request where the host permission is held (`HEAD`, headers are the whole payload wanted) and a `no-cors` GET otherwise; `probeVerdict` deliberately does NOT consult whether the frame painted, and this is the one rule here that has been got wrong twice: yielding to a painted frame sounds right (don't tear down a working app) but against a dead host Chrome's error page paints in milliseconds and fires `load`, so "painted" is always true and the suppression could only ever fire — the panel could never appear for the most ordinary failure it exists to report. `blocked` was already exempt for exactly this reason; `unreachable` is too, so the distinction is gone. The accepted cost: a frame painted from cache during a network blip shows the panel over a surface that worked. A wrong URL is permanent and hits every tab open, the blip is transient, and the panel carries Retry. Three accepted quirks, documented in `extension/README.md`: Chrome focuses the address bar on a new tab (Momentum has it too — nothing tries to steal it back); the framed app gets its OWN storage partition, so it is a separate sign-in and separate `localStorage` prefs from the same app in a normal tab; and **the browser sensor is BLIND to this tab** — it reads the active tab's URL, which is `chrome-extension://…`, and `scrub.js` drops non-http(s) schemes, so time on the ambient home records no interval. A stated gap, not a fix — closing it would mean changing what the extension records.
- **NOT wired to Trackable, and that is still true (2026-08-12).** Scoring, productivity judgements and any percentage remain a separate later design; `browser_intervals` is the honest raw substrate they would read. Landing this in the trackable surface would produce confidently wrong focus percentages. **Surfacing an `opened X` row in the activity feed is NOT that**, and the distinction is the one a future session most needs to keep: the feed rows say WHAT happened and WHEN, derive from nothing but the intervals themselves, mint no Trackable, and make no claim about whether the time was well spent. A row in the log is not permission to score. **Attribution — binding observed attention to a Promise — landed 2026-08-15 and is the one thing on that list now built**: see the Focus attribution section. It reads these rows, writes nothing to them, and still mints no Trackable.

## Device rows — `opened X` in the log and the timeline (2026-08-12)

**Three sensors, one row.** The phone's iOS Shortcuts pings, the Chrome extension's tab focus and the desktop shell's frontmost app all read as the same amber `device` row in the log sheet's `all` filter and as the same quiet marker on its `timeline` tab. **`app/services/device_activity.py` owns that vocabulary** — the phrasing, the two grouping constants, and the derivation — so the three can't drift into three dialects.

**The trap this design exists to avoid: `POST /events` is NOT the path.** `event_service.log_event` mints a NEW Trackable per unique `"{subject} {event}"`, which is right for a dozen phone triggers and catastrophic for browser hosts and app names — hundreds of definitions flooding the log matrix, an order of magnitude worse than the Shortcuts crowding that already needed its own right-hand bucket and its own exclusion from the compact dots. **Same presentation, different storage: the FEED is the integration point, not the Trackable table.** `tests/test_device_activity.py` asserts that ingesting attention mints zero Trackables.

**The derivation, and why it is two rules and not one.** The interval sensors close an interval on every switch — that is what makes their durations honest and what makes them useless as a log.
- **`OPEN_GAP` (5 min, captain-decided)** defines what an OPEN is: the first focus of a name after five minutes away from it. Alt-tabbing to Slack and back opens nothing; coming back after lunch does. `opens_from_intervals` is pure, so the rule is testable without a database.
- **`CLUSTER_GAP` (60 min)** decides how many ROWS a day of opens is worth. The gap rule alone is not enough, which is MEASURED rather than assumed: a simulated workday of 860 intervals across 14 hosts and 8 apps yields **408 opens** — with a dozen names in rotation you genuinely leave each of them for five minutes several times an hour — and **39 rows** once opens are chained into runs. That is not a second invention: 60 minutes is the number `event_service` has always used to collapse a run of Shortcuts pings into one card, and it now IMPORTS the constant from here so all three sensors group identically by construction.
- A run is timed and keyed at its **FIRST** open, which is where this deliberately diverges from `event_service` (that stamps a run at its LATEST ping). A row saying "opened cursor" belongs at the moment it was opened; anchoring at the latest put every all-day name at the end of the day and made 18 of a 39-row day land in one hour, reading as a burst of activity that never happened. The first open is also the stable anchor — and, since the window is a local day (below), a stable KEY: a run's anchor is its first open *within that day*, so it can't move when a different reader asks about the same day.
- `host_label` is COSMETIC only (`www.leetcode.com` → `leetcode`; a subdomain survives as `mail.google`; an unknown TLD is left entirely alone rather than guessed at). The raw host/app stays on the row as `name`.

**Wiring, and THE WINDOW IS A LOCAL CALENDAR DAY.** `activity_service` grows a `kind: "device"` source. The other sources page by `ORDER BY … DESC LIMIT n`, which the gap rule cannot use — deciding whether an interval is an open needs the interval BEFORE it, and that is the direction a DESC-limited query throws away — so this source reads a WINDOW instead. That window used to be `[cursor - lookback, cursor)`, and it produced **two** bugs from one seam: a span the cursor jumped over in a single page was derived by no page at all, and a run's `×N` counted only the opens older than whatever cursor happened to ask, so the same afternoon read `×5` on one page and `×3` on the next. So the seam MOVED rather than taking a third patch: `device_activity.device_opens(db, start_day=, end_day=)` derives whole LOCAL days (`Settings.nudge_tz` via `common.local_day_bounds`, tz-aware midnights computed PER day so a DST switch can't misfile an hour — the same rule the browser summary's buckets use, now single-owned in `common`), and **callers SELECT days; they no longer define windows**. "What opened on day D" therefore has one answer however the reader paged there. A run crossing local midnight SPLITS into one row per day, each anchored at its own first open — the grammar `focusTime.ts::splitSegmentsByDay` already uses — which also makes the key stable per (layer, day-part). The paging cursor is still the merged page's oldest item, so `_device` is derived LAST and told how far the page reaches (`_page_reach` = the `limit`-th newest non-device item, or the oldest when there are fewer than `limit`) and converts that to a DAY SET: `_DEVICE_MIN_DAYS` (3) is the minimum, `device_activity.MAX_DERIVED_DAYS` (31, the spirit of `MAX_SUMMARY_DAYS`) the floor when nothing bounds the step and the cap on any one read. A day window reaches past the cursor by design — the count describes the DAY — so `_device` drops rows newer than the cursor after deriving, never before. **The reach-back that protects the window's leading edge cuts on `ended_at`, not `started_at`** (`device_activity.GAP_REACH`/`SCAN_REACH`): relevance as a predecessor is decided by when an interval ENDED, and a session longer than the 65-minute grace is ordinary (idle only closes one after ~a minute of no input), so a `started_at` bound alone loses the Cursor 21:30→00:20 row that proves a 00:22 focus is a continuation — the fake midnight `opened` the grace exists to prevent, arriving through a third door. Since only `started_at` is indexed on both tables, the query is an INDEXED PREFILTER (`started_at >= start - SCAN_REACH`) PLUS THE EXACT PREDICATE (`ended_at >= start - GAP_REACH`); the widened prefilter is provably sufficient only because `interval_ingest.MAX_INTERVAL_SEC` rejects anything longer, so `SCAN_REACH` imports that cap rather than restating 6h. The SCAN is capped too (`MAX_SCAN_INTERVALS`, 10k per table per read, both capped independently); truncation is at the OLD edge and the effective floor rises to the oldest surviving interval PLUS `SCAN_REACH` (a row cut away could itself have run up to `MAX_INTERVAL_SEC` past its own start), so a predecessor that was cut away can never be mistaken for absence and mint a fake `opened` at the truncation boundary. **A day the floor cuts INTO is then dropped WHOLE** (`device_activity.fully_derived_days` — a day is derived only when its own start is at or after the floor, the full reach included): reporting it would re-anchor its runs at the first surviving open and undercount them, so the same day would read `×20` on a narrow read and `×12` on a wide one, which is precisely the bug day-binding exists to remove. The cap therefore costs whole DAYS at the old edge, never a wrong count on a day it returns; a missing row is a gap the reader can see. Both bounds log when they bite, the day-drop naming the oldest fully-derived day; a silent cap reads as complete coverage. `focus_service.stream` emits the same `{type:'event', label, kind, at, count}` card the Shortcuts pings do, so the timeline renders one row shape — it already worked in local days, so it just asks for the newest `DEVICE_STREAM_DAYS` (7) of its range, and it reads the row's **`phrase`** (the sentence without the count, since the timeline renders `×count` itself) rather than rebuilding `opened …`, so the verb is written in exactly one place. `event_service.list_recent_events` renders its label through that same `event_phrase` too, so the PHONE's timeline rows changed on purpose — `opened instagram`, not the raw trackable key `instagram open` (three sensors printing one event three ways is three vocabularies). `/focus/dashboard`'s `rollups` line is untouched and still shows the raw key. The frontend adds one `case "device"` in `LogSheet.labelFor`, returning the SAME `DEVICE_ROW` constant the `shortcuts` arm returns — one constant, two arms, so they cannot drift. **`recent_activity` excludes device rows at source** (`exclude_kinds={"message", "device"}`): a handful of openings is a readable log for a human but is not state Gooni must reconcile a reply against, and it would push promise/trackable events out of a ~8-line budget.

**Storage: `app_intervals`, a table of its own.** Not a `source` discriminator on `browser_intervals`: `host` is a hostname and `app` is an application name, and every existing browser read (the extension popup's per-host ranking, the SQL `summarize` fold, `GET /browser/intervals`) would have to grow a filter it doesn't need, with an app listed as a visited domain as the cost of missing one. What IS shared is the code — **`app/services/interval_ingest.py`** owns the `client_id` idempotency boundary, the per-row SAVEPOINT, the recompute-durations rule and the validation limits for BOTH sensors, so the two can't disagree about what "accepted" means. Durations are recomputed server-side (clocks are read, arithmetic isn't trusted) and a row that is backwards, sub-second, past `MAX_INTERVAL_SEC` (6h) or in the future is REJECTED with a reason rather than clamped. **Each row inserts inside its own SAVEPOINT** (`db.begin_nested()`): the `client_id` pre-filter is only a fast path, and when two concurrent flushes race, the loser's UNIQUE violation must unwind ONLY its row — a plain `db.rollback()` discards every row already inserted in the batch while the response still names them in `accepted`/`stored_ids`, and the client deletes exactly those ids from its buffer. An over-reported accept is permanent loss; an under-reported one just costs a redelivery that dedups. Migration `a5c81f30d7e2`.

## Focus attribution (2026-08-15 — `app/services/focus_attribution.py`, ADDITIVE)

The layer `BrowserInterval`/`AppInterval` were kept clean for. **A named task plus a bounded timer IS the attribution mechanism** — every interval overlapping a focus session's windows belongs to that Promise BY CONSTRUCTION. There is no classifier, no embedding, no keyword list and no heuristic anywhere in the module — the rail's `/focus` entry only navigates there, `/focus` still has exactly one door to START a session (a task row): attribution stays free only while starting a session requires naming what it is for.

**Derived at READ time, never stamped at ingest — the one decision that matters.** The tempting alternative is wrong by construction rather than merely worse: both sensors BUFFER (the extension retains through `5xx`/`429`/`404`/`401`/offline, the desktop shell persists across quits), so an interval measured at 14:30 legitimately arrives at 18:00 and would be filed against whatever is running THEN — silently, permanently, and hardest on exactly the days the network was bad. `tests/test_focus_attribution.py` pins that case; it is the assertion that fails if someone "optimises" this into `interval_ingest`. It is also the only option available: session state is a client store (`useFocusSessionStore`), so at ingest the server does not know a session is running at all.

**No new table, no column, no migration.** Two inputs that already exist: the `focus` trackable's entries (the session windows) × `browser_intervals` + `app_intervals` (the attention). `attribute(db, start_day=, end_day=, promise_id=)` overlaps them and returns `{start, end, promises: [{promise_id, title, promise_exists, state, focused_minutes, precise, truncated, days[], browser, app}], warnings}` behind **`GET /focus/attribution?days=&end=&promise_id=`** (`fetchFocusAttribution` in `api.ts`).

**`value_json.segments` is the precision fix, and its absence is REPORTED.** An entry's `started_at`/`ended_at` are the day's ENVELOPE — `splitSegmentsByDay` folds every focus run on a day into one entry, so a session paused for lunch has an envelope spanning the lunch, and overlapping it credits the Promise with the lunch scroll. So the write path now also emits the exact clipped runs (`segments`, sorted, midnight-clipped) and the reader prefers them. An older entry without them still attributes, from the envelope, flagged **`precise: false`** — its seconds are an upper bound. Flagged rather than dropped and rather than silently mixed: a number that may be too high is useful when it says so and poison when it doesn't. Same free-form-Text trick as `promise_id`/`truncated`; additive, so nothing that reads the entry today breaks.

**Four honesty rules, each the inverse of a bug this shape makes easy.** (1) **`focused_minutes` is the TIMER's number**, straight off `value_numeric`, never recomputed from what the sensors saw — a window nothing observed keeps all its minutes, which is the case that must not read as zero. (2) **`coverage` is a claim about the SENSORS**, not the human: an uninstalled extension and a genuinely idle browser produce the same `0.0` and opposite claims, so it sits beside the minutes and never replaces them. (3) **Overlap, not containment** — a tab held 40 minutes across a 12-minute session contributed 12, and the straddling interval is the ORDINARY one since intervals close on switches and idle. An interval is COUNTED once per (promise, day, name) however many windows it spans (a tab open across three pomodoros is one visit), while its SECONDS sum across them. (4) **No score, no percentage, no productivity judgement, no ranking of one Promise against another.** `rank()` returns the head AND the tail's `other_sec` so a head never reads as the whole; the day/scan caps append to `warnings` rather than truncating silently.

**Shared constants, not restated ones.** `MAX_DERIVED_DAYS` (31), `MAX_SCAN_INTERVALS` (10k/table/read) and `host_label` are imported from `device_activity`; `MAX_INTERVAL_SEC` from `interval_ingest`, which is what makes the indexed-`started_at` prefilter (`started_at > span_start - MAX_INTERVAL_SEC`, plus the exact `ended_at > span_start` predicate) provably sufficient — the same trick and the same reason as `device_activity.SCAN_REACH`. Days come off the entry's own `date` column rather than being recomputed from `Settings.nudge_tz`: that column is the day the log matrix already shows the minutes on, and re-deriving would make this read disagree with the column it describes.

**Deliberately no new UI.** The layer + route + fetcher + types ship; which surface renders it is a product call, and the missing piece was never a screen. `focus_attribution.FOCUS_TRACKABLE` must stay in sync with `focusTime.ts::FOCUS_TRACKABLE` — one definition, get-or-created by name from the client.

## Desktop shell (2026-08-12 — `desktop/`, Electron, ADDITIVE)

Gooni without a browser tab, and — the actual reason it exists — **one owner for the focus-cam sidecar**. Full rationale: `desktop/README.md`.

**THE decision: the shell points at the DEPLOYED backend** (`apiUrl` default `https://gooni-bot.fly.dev`). Ambient requires always-on, and a localhost default captures nothing whenever `dev.sh` isn't running — the same trap the extension's `DEFAULT_BASE_URL` had. Configurable, but the tray says so out loud when `apiUrl` is local. That default is FORCED onto the web frontend too: `frontend/src/services/api.ts::BASE` now prefers **`window.__GOONI_API_URL__`** (injected by `src/preload-app.js` before any page script runs) over the build-time `VITE_API_URL`, because a bundle built for another environment would otherwise fall through to localhost inside the shell. Undefined in a browser → unchanged there. `SettingsModal` dropped its duplicate `API_BASE` and imports `BASE`, so there is ONE base URL.

- **`desktop/src/main.js` is the ONLY file that imports electron.** Everything with a decision in it is chrome-free and unit-tested (`npm test`, node:test, zero deps, no Electron, no network — same split `extension/` uses): `config.js` (defaults/merge/env precedence — env > file > default; unknown keys DROPPED so a typo can't look like it configured something), `sidecar.js`, `logbuffer.js`, `traymenu.js` (the menu as DATA, so the wording is asserted), `api.js`, `reply.js`, `token.js`, `jsonstore.js` (the durability boundary both state files go through — atomic write, loud loss), and the four frontmost-app sensor modules below.
- **The frontmost-app sensor (2026-08-12)** — the OS half of "what did I actually do today", and the source of the `opened <app>` rows in Gooni's log (see the Device rows section). Four chrome-free modules: **`frontmost.js`** (the OS read), **`appfocus.js`** (the interval state machine), **`appreporter.js`** (buffer + delivery), **`appsensor.js`** (the loop that joins them). `main.js` supplies the two OS reads and forwards `powerMonitor` events; config lives under `appSensor` (`enabled` ON by default — an installed sensor that senses nothing until someone visits a settings screen is the same lost data with a better excuse — plus `pollMs`/`idleSec`/`flushMs`, each CLAMPED, since a 100ms poll spawns `osascript` ten times a second forever). Net: `desktop/tests/appfocus.test.js` + `appsensor.test.js`.
  - **Mechanism: `osascript` asking System Events, spawned per poll.** Electron has no frontmost-app API. A maintained npm package would have been a new dependency AND a prebuilt native addon to re-match the Electron ABI on every upgrade; a native helper of our own would be a second unsigned binary for macOS to forget the permission grant of. The scripted query costs a process spawn every `pollMs` and a few tens of ms of CPU, which is real but unnoticeable at a 4s cadence, and it buys zero dependencies and nothing to codesign. The precision it gives up does not matter, because the row it feeds is "opened X after five minutes away". Needs macOS **Accessibility**; the build is unsigned, so a re-prompt after a rebuild is expected and documented, not a bug.
  - **The honesty rules are the browser sensor's rules, restated.** **An unobserved stretch is never credited** — `_close` clamps DOWN to the last confirmed observation and flags `truncated` whenever the requested end runs past it by more than `observationGapMs` (injected by the sensor as `max(5 × pollMs, 15s)`, since "how big is an ordinary gap" is a question about the poll cadence and the pure module holds no cadence of its own). The 6h cap cannot catch this: `osascript` wedging or an Accessibility grant revoked mid-session stops `lastSeenAt` advancing while the interval keeps accruing, and a forty-minute hole sails straight through a six-hour ceiling as a CLEAN row. The sensor also does not WAIT for a later real event to notice — once observation has lapsed it closes the interval itself (`end_reason: "unobserved"`) and clears the salvage anchor, because a blind sensor sitting on a stale open interval must not be an invisible state. **That check runs on EVERY tick, not only when the query fails**, and the two are different holes: the query can stop answering, or polling can stop happening (the machine sleeps without `suspend` landing — SIGSTOP, a forward clock jump, a wedged main process). In the second case the query answers normally on the far side and names the SAME app, and `focus`'s same-app branch is deliberately continuity-preserving (an unconditional close would chop a real hour of work into poll-length slivers), so nothing there could catch it and the overnight gap was absorbed into the interval and reported clean. The staleness question is therefore asked before `focus`, through the same `_closeUnobserved` the failure branch uses — one predicate, one owner — and the app being frontmost NOW opens a fresh interval starting now. Clamping is downward-only, so a backdated idle close, a lock, a suspend and a clean quit all stay measurements. **Idle is checked FIRST and idle WINS** — a frontmost app is not an attending human, walking away never changes which app is frontmost, so polling "who is frontmost" alone would credit every lunch break to whatever was on screen; `powerMonitor.getSystemIdleTime()` gives the exact elapsed idle, so the close is backdated exactly (better than the extension's fixed-threshold backdate). An idle read that THROWS fails closed. **A salvaged interval is flagged `truncated` and closed at its last confirmed observation**, never at the next launch — otherwise quitting at 6pm and launching at 9am reports a fifteen-hour session; the same 6h cap the server rejects past (`interval_ingest.MAX_INTERVAL_SEC`) and `/focus` puts on a session applies here. **Sleep and lock close with a REAL end time** (`powerMonitor` delivers both before the machine goes away), which is why a normal lid-close is a measurement and only a hard crash is salvaged. **Durations are recomputed server-side.** A generation counter makes the async tick safe: a power event bumps it, and a query resolving afterwards discards its answer instead of reopening an interval for a sleeping machine.
  - **Delivery is retain-by-default**, same ladder as the extension: destroy only on `400`/`413`/`422`; `5xx`/`429`/`404`/`401`/offline/timeout all keep the buffer; **on QUIT, durability and delivery come apart** — the `shutdown` interval is closed and PERSISTED synchronously first (skipping that is what turns a clean quit into a truncated salvage next launch), then delivery gets `STOP_FLUSH_BUDGET_MS` (2s) and the shell quits whether or not it landed. The reporter's own `FLUSH_TIMEOUT_MS` stays 20s, which is right for a background flush and wrong for a windowless menu-bar app quitting on a captive portal, where the connect is accepted and then hangs; waiting it out buys nothing, since the rows are already on disk and `client_id` makes the next launch's redelivery a no-op. The flush is not cancelled, only the WAIT is bounded — which matters for `reloadConfig`, where the process carries on and a late success is a real delivery. The **sidecar** stop stays fully awaited regardless: it holds the camera, and an orphan with the privacy light on is the failure the supervisor exists to prevent. a 2xx acks the WHOLE batch (acking only `stored_ids` would strand every duplicate forever, since duplicates are counted and not named); overflow drops the oldest and COUNTS it; concurrent flushes join rather than posting twice. A refused batch is removed **by `client_id`**, the same way the success path removes an accepted one — `batch` is captured before the await and `add()` can splice the FRONT of the buffer for overflow while the request is in flight, so a positional slice would destroy that many rows that were never sent; the destroyed COUNT is what actually left, so a row already lost to overflow isn't booked twice. State lives in **TWO** JSON files under `userData`, and the split is the point: the buffer changes only on add/flush, while the open-interval salvage anchor is rewritten on EVERY poll (a stale `lastSeenAt` would credit everything up to a crash). Sharing one file meant a day-long outage re-serialised the whole ~1MB backlog synchronously on the main process every 4 seconds; an unchanged anchor now doesn't touch the disk at all. **Both files go through `desktop/src/jsonstore.js`, which is atomic and loud** — a write lands on a sibling temp file and is RENAMED onto the target (same directory, since rename is only atomic within a filesystem), so a kill or a power cut leaves the whole old document or the whole new one, never the truncated one an in-place `writeFileSync` produced; and a MISSING file stays the quiet first-launch path while an UNREADABLE one preserves its bytes alongside (`<name>.corrupt-<stamp>`), logs, and feeds a **third** loss counter, `corrupted`. A write that does NOT land is the fourth state and the one that looks healthiest — `userData` fills up or loses permission, the document freezes at its last good version while memory moves on, and a crash then takes the difference — so `write()` answers whether it landed and `unsavedWrites()` is the run of failures since the last one that did (in memory by definition: persisting is the broken thing). It is a LIVENESS signal, not a loss: the tray prints `NOT SAVING (n writes failed)` ahead of every historical count, and one transient failure clears on the next success. Third on purpose: `dropped` is buffer overflow and `refused` is a server refusal, the tray labels those two specifically, and a lost state file takes an unknown backlog AND both of those counts with it — so the count is DERIVED (`jsonstore.losses()` counts the quarantine files, which outlive every state file) and never persisted by the reporter — a running total has to be written by somebody, and the document it would live in is the one corruption destroys, which is how two writers with different notions of the total made the number wrong in both directions (double-counting a second loss on one file, discarding the other file's history when it went). Net: `desktop/tests/jsonstore.test.js`. The tray carries an `App sensor:` line, and the **missing-Accessibility grant is the only sensor state promoted to the headline** — a buffered backlog is normal and a permanent warning is one you stop reading, but a refused grant never clears on its own and until it does the sensor records nothing while looking installed.
- **`sidecar.js` — the supervisor.** The sidecar is NOT in this repo (separately-built local macOS daemon, contract in `docs/focus_cam_contract.md`), so the shell supervises whatever `sidecar.command` names. States: `disabled` (off on purpose, not a problem) · **`unconfigured`** (no command — LOUD in the tray; it never degrades into a quiet "no sidecar today", and it's the state a fresh install sits in) · `failed` (path not executable, WITH the path — rather than an ENOENT crash loop that reads like a broken sidecar) · `running` · `backoff` (1s→2s→4s… capped 60s; a run ≥30s resets the ladder, so one death isn't a loop) · **`crashlooping`** (5 consecutive fast exits — still retrying, since the cause may be transient, but no longer claiming health). Spawned **detached** so `stop()` can SIGTERM the process GROUP (Python daemons fork helpers) then SIGKILL after 5s; `before-quit` AWAITS it, and SIGINT/SIGTERM/SIGHUP route into the same path — detached means the child does NOT die with us, and a camera-holding orphan leaves the privacy light on with nothing owning it. Output → `~/Library/Logs/gooni-desktop/sidecar.log` + a 500-line ring, supervisor lines prefixed `[shell]`.
- **Capture hotkey** (default `CommandOrControl+Shift+Space`, also `--capture` on argv / a second launch, so Raycast/Shortcuts can summon it). It opens the shell's OWN frameless overlay (`renderer/capture.*`), pre-loaded and hidden — navigating a remote SPA to a capture route would cost a page load exactly when the thought is fragile. It posts through `createConversation` + `/conversations/:id/messages`, the SAME path the ambient wave uses, so nothing about the orchestrator (extraction, glow, memory) is bypassed. **The HTTP happens in the MAIN process**: the backend's CORS is an allowlist, a `file://` renderer would be blocked, and widening `ALLOWED_ORIGINS` for a desktop window would weaken it for the web app. A failed send KEEPS the typed text. A hotkey already claimed by another app raises a dialog rather than silently doing nothing.
- **Token**: `config.token` → sha256(`config.authPassword`) (same derivation as `common._expected_token`) → **harvested** from the app window's localStorage by the preload after you sign in once (the normal path). `source` is carried, not just the token — "not signed in" and "the token you pasted is rejected" need different advice.
- **The window (2026-08-15 polish pass).** `titleBarStyle: hiddenInset` gives the page the whole window, traffic lights included — which also means the OS has nothing left to drag by, so the shell had shipped an **unmovable window**. The frontend volunteers the drag region instead: the preload exposes **`__GOONI_DESKTOP__`** (`{platform, openedTheme}`) and `frontend/src/services/desktop.ts::dragRegion` emits `-webkit-app-region` ONLY when it is present — a positive signal from the shell, not a UA sniff, because the same deployed bundle also serves a browser tab and the extension's new-tab frame where the rule is meaningless. `AppHeader` is the handle (its date is dead space by design); every interactive child opts back out with `no-drag`, since a drag region swallows clicks. `minWidth`/`minHeight` (880×640) exist because the home is FRACTION-pinned — see `ROWS_MAX`'s floor in `AmbientHome` — so a short enough window drives the task list to nothing; the floor and the minimum are two ends of one rule and neither is sufficient alone.
- **Launch is not a flash.** Three separate causes, all fixed together: the window was `show()`n at `whenReady` with the page still loading (an empty rectangle, longest on a slow network) → the FIRST show waits for `ready-to-show`, with a `FIRST_PAINT_GRACE_MS` deadline so a page that never paints can't lock you out, and `did-fail-load` counts as painted because the failure page IS the thing to show; `index.html` hardcoded `background: #FAFAFA` → an inline boot script resolves the persisted `gooni_theme` into `--gooni-void` before the bundle runs (duplicated colours on purpose — nothing from the bundle can run that early); and `backgroundColor` was a hardcoded `#000000` under an app that DEFAULTS to light → **`desktop/src/appearance.js`** remembers the harvested theme (`appearance.json`, a preference not a credential, so its own file at 0644 rather than token.json's 0600) and the next launch opens on the ground the app is about to paint. The theme rides the token's existing 5s poll — `localStorage` fires `storage` only in OTHER documents, so a theme flipped in this very window (the only place it is ever flipped) would never be reported by an event listener. Net: `desktop/tests/appearance.test.js`.
- **The capture overlay follows the app's theme.** Its entire stylesheet reads four channels (`--ink`/`--surf`/`--accent`/`--warn`), so following the app is a variable swap under `:root[data-theme="light"]`, not a second stylesheet; DARK stays the default, so a first launch that has never seen the app still renders the surface this was designed on. It is long-lived and pre-loaded, so it can only learn about a flip by being TOLD (`capture:theme`) — a value read at open would land one summon late.
- **Tray** is silent when healthy and shows `⚠` + EVERY problem (not just the first — a fresh install has three: unconfigured sidecar, no token, and whatever `apiUrl` says). Launch-at-login is a no-op when `!app.isPackaged` — `npm start` would otherwise register *Electron*, not Gooni, pointed at a checkout path.
- **SELF-SIGNED codesigning (2026-08-15); notarization still out.** macOS ties camera/Accessibility/Screen-Recording grants to a binary's code-signature identity, and unsigned/ad-hoc builds got a new identity every rebuild — every rebuild re-prompted every permission. The build now signs with a self-signed `Gooni Dev Signing` cert (one-time `desktop/scripts/setup-signing.sh`, idempotent; `build.mac.identity` in `desktop/package.json` makes every `npm run pack`/`dist` sign automatically), so the designated requirement is stable across rebuilds and grants persist. NOT ad-hoc (`-s -`) on purpose — an ad-hoc DR is the per-build cdhash, which re-prompts. No Apple Developer account; notarization/Developer-ID stays out of scope, so the shell still leaves the camera grant to the sidecar for now — self-signing is the prerequisite met, not the change itself.
- **A shell does NOT reduce the number of moving parts** — mediapipe keeps Python alive regardless, and this adds an Electron process. What it buys is one owner, presence, and the hotkey.

## Schema changes (Alembic)

```bash
# After editing app/db/models.py:
source venv/bin/activate
alembic revision --autogenerate -m "what you changed"
# Review the generated file. SQLite quirks: Boolean→INTEGER (cosmetic),
# DateTime→TEXT (cosmetic), missing FK constraints (SQLite doesn't enforce).
alembic upgrade head
# Commit the new revision alongside the model change.
```

`alembic upgrade head` runs on uvicorn boot via `_alembic_upgrade()`. Fresh DBs walk from baseline to head. **Half-applied-state recovery:** boot catches "already exists" OperationalErrors and stamps to head. **Migration-author conventions:** inspector guards (`has_table` / column checks) so re-runs are no-ops; `if_not_exists=True` on create_index. **Dropping columns whose FK targets are already-dropped tables:** batch_alter reflects the table and follows FKs → `NoSuchTableError`; stand up empty phantom parents for the rebuild, drop indexes touching the doomed columns first, drop phantoms after — see `4d9c44f8f546` for the working pattern.

## Code Patterns

- **Zustand persist**: bump key on shape change to avoid stale state
- **Module-style services**: most `app/services/*.py` are function modules (or one instance at bottom)
- **FastAPI `db: Session = Depends(get_db)`** — session per request
- **Optimistic UI**: `createNote` adds temp note, replaces w/ API response
- **React StrictMode**: kept intentionally
- **hasChanges ref**: NoteEditor only saves if the user typed
- **Public routes** `/public` + `/public/$noteId` standalone (no sidebar/auth); grouping label = first tag
- **Deferred embedding columns**: `Note.embedding`, `Note.classified_embedding`, `Memory.embedding`, `Message.embedding`, `Promise.embedding` wrapped in `deferred()`. Similarity callers MUST use tuple queries.
- **Deterministic > LLM** for anything user-facing that ranks/surfaces/promotes (overlay, glow, matchers). LLM only parses.
