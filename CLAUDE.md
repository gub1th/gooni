## Goal

Gooni = personal AI notebook → ambient home assistant. **Ambient-loop v2 (2026-07, PRD note #389) collapsed the primitive layer to 6 core tables.** The loop:
1. Every thought — web chat, WhatsApp, Telegram, notes — lands in one append-only log with a uniform ack (no dispatch fork at capture time)
2. The extractor annotates commitment-shaped messages with a glow; Daniel promotes them to Promises with one tap (or dismisses); measurements log to Trackables (web matrix, or an explicit whole-basis chat log tool — NOT auto-extracted)
3. A hover-summoned frosted overlay shows what matters right now (deterministic rankers, no LLM)
4. Memory built from notes/chat in SQLite `memories` table (extract → reconcile via LLM, cosine-retrieved at chat time) — KEPT through the v2 nuke (Daniel's override; chat recall is load-bearing)

Mobile capture via bots: Telegram (live), WhatsApp (live), iMessage (code shipped, awaiting Mac+BlueBubbles). All route through `MessagingChannel` ABC in `app/services/messaging/`.

## Core data model (post-v2)

**5 primitives + Memory:**
- `Note` — universal capture atom. Tags (JSON list, lowercase, deduped) replace Spaces for ALL organization. `excerpt` cached preview; `is_draft`/`is_pinned`/`is_public(_pinned)`. `GET /notes` (flat list, `?tag=` filter), `POST /notes`. (The `status` graduation lifecycle + 5am-batch session cols were dropped in the lean sweep `4d9c44f8f546`.) Two placement cols (migration `884013e244b2`): `log_date` (Date, indexed) marks a **daily-log note** — the log-matrix "note" column, one per date, `daily` tag, `GET /notes/daily?days=&end=` + `PUT /notes/daily/{date}` (empty body → delete = cell-clear); `home_pos` (JSON-text `{x,y}` viewport fractions) marks a **sticky note** parked on the ambient home, `sticky` tag, `GET /notes/sticky`. Both are real Notes (searchable, embeddable) — not new primitives. **Two more subtypes arrived with the focus convergence** (migration `f4c81a92de70`): the `thought` tag (a single logged thought, `parent_note_id` → its batch) and `thought-batch` (a run of thinking; `title` = Claude's third-person label). Same trick as `daily`/`sticky` — tags, not tables. Notes also gained **`topic_id`** (nullable FK → `topics`), a real FK rather than a tag because `Topic` carries a decay curve anchored to `last_touched`, and computing that by LIKE-matching a JSON column would be slow *and* wrong the moment a topic is renamed. Tags stay for every other kind of grouping.
- `Promise` — THE actionable primitive (absorbs Todo/Habit/Focus **and, since the 2026-08-08 focus convergence, Reminder**). `cadence` (`once|daily|n_per_week|permanent_do|permanent_never`), `cadence_target` (N for n_per_week), `is_important` (user-set; overlay input), `parent_promise_id` (self-FK nesting — a "Focus" is a Promise with children), `inferred_due` (local-EOD anchored, naive UTC), `needs_clarification`, `slip_count` (cosine vs past broken), `source_message_id`, deferred `embedding`, plus the two columns absorbed from Reminder (migration `f4c81a92de70`): **`owed_to`** (nullable FK → `focus_people`; null = owed to yourself, the common case — the one thing Reminder could express that Promise couldn't) and **`due_is_default`** (true when NOBODY chose the deadline — `set_reminder` defaults an omitted due to today's local EOD purely so the row lands on the dashboard's short-term/longer-term split). Lifecycle `active → kept|broken`; `auto_mark_overdue` sweeps once-cadence only (recurring never auto-breaks on a date) **and skips `due_is_default` rows** — breaking a deadline Gooni invented would mark Daniel broken at midnight every night on a commitment he never made. Chat-side closure via `find_active_match` (substring → unique-word-overlap → cosine ≥0.60; top-2-within-0.05 → ambiguity refusal → "which one?" ack). CREATES from chat do NOT auto-insert — see glow below. `DELETE /promises/{id}` hard-deletes (undo path).
- `Trackable` + `TrackableEntry` — generic measurement (Notion-tables model). Definition: `name` (lowercase-unique), `kind` (`boolean|numeric|json`), `agg` (`sum|last` per-day fold), `unit`, `cadence`, `target`, `is_important`, `schema_hint` (JSON hint incl. optional `direction: limit|floor`), `source` (`manual|chat|whoop|leetcode|shortcuts|derived|focus_cam`), `parent_promise_id`. Entry: sparse `value_boolean|value_numeric|value_json` + `(trackable_id, date)` index; multiple rows/day legal. New tracked thing = one INSERT. 8 system trackables (calories/protein sum-agg; weight/exercise/note + three personal habit flags, last-agg) + feed masters (`whoop`, `leetcode` json) + numeric mirrors. **Shortcuts events** (`source=shortcuts`): an iOS Shortcuts automation (App Opened, Arrive/Leave a location, CarPlay, charger, NFC…) POSTs `{subject, event, at?}` to `/events`; each ping is +1 on a per-`"{subject} {event}"` sum-agg numeric Trackable created on the fly (`event_service.log_event`), with the clock time stored in `value_json.at` (the seam for future arrive+leave dwell/session math). No hardcoded event vocab — a new trigger needs ZERO backend change. No Apple Screen Time API (needs the paid FamilyControls entitlement), no session pairing yet (counts only). Appears in the **expanded log matrix** (`LogTable`'s `isDaily` keeps them) + the activity rail as "device" events, but is EXCLUDED from the **compact daily-dots glance** (`LogDots`'s `isDaily` drops `source=shortcuts`) — device telemetry is ambient, not priority, and a handful of triggers crowd the single-row glance and bury the OG trackables. The compact glance stays priority-only (system + manual); NOT the special whoop/leetcode feed tiles. **Focus-cam** (`source=focus_cam`): the local webcam focus sidecar's data (see the Focus-cam section) is WALLED off from EVERY existing trackable surface — `trackable_service.HIDDEN_SOURCES` drops it from `list_all` (so `/trackables` matrix/dots + overlay + chat `read_trackable` never see it) and `activity_service._trackables` filters it from the rail; read ONLY via `/focus/cam/*`. Stronger than the `shortcuts` client-drop (enforced at the query, no client can surface it). **24hr Fitness sync** (`app/services/fitness_24hr.py`): reverse-engineered personal-interop pull — logs into 24hourfitness.com (captcha not backend-enforced → `captchaToken:null`), reads the day's club check-ins, and if any AND the `exercise` cell is empty, writes `exercise="gym"` in-process via `daily_metric_service.set_cell`. Idempotent + never clobbers a manual push/legs label. Runs SERVER-SIDE from the hourly `_integration_refresh_loop` in `app/background.py` — NOT a cron: the one periodic job that also refreshes whoop + leetcode (each sub-refresh independently guarded, off the event loop via `asyncio.to_thread`). Fills the log even on days the app is never opened. Secrets = fly secrets `TFHF_USERNAME/TFHF_PASSWORD` (in-process write → no bearer). `scripts/sync_24hr_fitness.py` = manual/debug CLI over `sync_today`. Setup: `scripts/README_tfhf_sync.md`.
- `Message` — the log substrate. Slice 3 glow cols: `has_actionable_signal` (sticky extractor verdict) + `signal_preview` (JSON `{signals, status: pending|promoted|dismissed, promise_ids}`). `GET /messages/log` = flat newest-first stream across all conversations w/ source badge. `POST /messages/{id}/promote` (runs `promise_service.create_from_signal` per draft), `/undo-promote` (hard-deletes exactly those promises, restores pending), `/dismiss-glow`. `GET /messages/{id}/trace` = full per-turn audit bundle (orchestrator step trace off `Message.trace` + `ToolCall` audit rows by message_id + paired user utterance + post-turn `Reflection`); assembles data that already existed keyed to the assistant message — powers the recent-chat ribbon's audit panel.
- `Edge` — semantic graph (`utters`, `derives_from`, …). UNIQUE on the 5-tuple; promise deletion clears its edges.
- `Memory` — KEPT (Daniel's override). Reconcile dance + cosine retrieval + MCP tools unchanged; the capability prompt block is gone (OBJECT_KINDS is the remaining anti-hallucination anchor). **Provenance (migration `c7e9a1f4b2d8`, 2026-07-12):** `source_message_id` (nullable FK → messages.id) is the chat twin of `source_note_id` — set to the user-utterance id in `_apply_add`, threaded from `orchestrator/core.py` (both reconcile trigger sites pass `user_msg.id` into the daemon `apply_memory_candidates` thread; the note path rides `RouterContext.source_message_id`). `GET /memories` resolves either id into a displayable `source` object (`_attach_sources` = 2 batch queries: Message preview + Conversation channel, or Note title); `null` for pre-provenance chat memories + injected prefs. `/memories` row surfaces it via `SourceTrace` (note → opens note; chat → reveals the source utterance inline). Forward-only — old memories stay null (unbackfillable).

**Infra kept:** `Conversation`, `ToolCall` (audit), `WaProcessedId`, `Attachment` (note-owned only now), `Reflection` (deterministic guards; facet promotion removed), `PublicProfile`, `Visit`, `OAuthToken`, `Settings`, `EvalSegment`/`EvalStepFeedback`/`EvalMessageRating`, `Trackable(Entry)`.

**Nuked (migration `e8b3c6d9f2a7`, 2026-07-09):** Space, List, ListItem, Todo, Focus, FocusCandidate, Habit, HabitEntry, BacklogTicket, FocusSession×3, FrictionEvent, GooniTake, McpCall, ClaudeUsageTurn, CapabilityFacet, NoteComment, Reaction, DailyMetric (rows pre-migrated to TrackableEntry in `f3b8d1c6a9e2`), GooniSnapshot, TrackedRepo (+ WhoopSnapshot/LeetcodeSnapshot in `d2f5a8c1e9b3`). Nuclear — git is the rollback. The lean sweep (`4d9c44f8f546`, 2026-07-10) finished the job: dropped the 25 orphan columns the nuke stranded (Settings nudge/idle cols, Note graduation/session cluster, unmapped FK leftovers).

## API surface

Route shapes are grep-able — one `app/routers/<domain>.py` module per domain (`visits, public, metrics, trackables, overlay, auth, misc, chat, speech, webhooks, settings, notes, promises, uploads, conversations, health, tool_calls, mcp, memories, eval, whoop, integrations, reflections, focus, focus_cam, display`). `focus` = the Focus SYSTEM (topics/thoughts/reminders, `/focus/*`); `focus_cam` = the webcam focus sidecar's brain side (`/focus/cam/*` — ingest + serve, see the Focus-cam section); `display` = the ambient kiosk's reconcile target (`GET /display`, `POST /display/control` — see the Ambient display section). Serialization in `app/serializers.py`. **`/mcp/*` router routes are DEAD** — `main.py`'s `app.mount("/mcp", focus_mcp.http_app)` shadows every path under the prefix (a Starlette mount wins over same-prefix router routes), so `mcp.py`'s `/mcp/notes/search` + `/mcp/memories/search` 404. Semantic note search was re-homed to **`GET /notes/search`** (declared BEFORE `/notes/{note_id}` so "search" isn't parsed as an id) and `api.ts::searchNotes` points there; the legacy `mcp/server.py` still calls the shadowed paths for `search_notes`/`search_memories` — those two MCP tools are broken until repointed. `speech` = `POST /tts` (text → MP3 bytes via OpenAI `tts-1`, voice `fable`; best-effort, 502→client stays silent). `integrations` = Google Calendar events CRUD (`GET`/`POST`/`PATCH`/`DELETE /calendar/events`, thin wrappers over `services/google_calendar.py`; `_serialize_event` flattens Google's start.dateTime-vs-start.date union into `{start, end, all_day}`) + GitHub + **`POST /events`** (generic iOS Shortcuts event ingest, body `{subject, event, at?}` → `event_service.log_event`; Bearer-authed like every route). 401 = calendar not connected.

## Focus system (2026-07-23) — CONVERGED into v2, 2026-08-08

The Claude-as-intelligence-layer pivot: **Claude** does extraction/intent/batching/query-formulation (via the Focus MCP connector, in-conversation); **Gooni** is pure persistence + a glanceable kiosk display; the display (not any agent) provides proactivity — an always-on screen showing what's due + which topics went stale needs no between-conversation machinery.

**Why that ended (migration `f4c81a92de70`).** Claude reached Gooni through TWO connectors — claude.ai's `/mcp` wrote focus tables, Claude Code's stdio `mcp/server.py` wrote v2 tables — and nothing linked them. **The mapping now** — `focus_service` is an ADAPTER over v2, the same shape `daily_metric_service` has over Trackable. Every public signature and response shape is unchanged, so `routers/focus.py`, both MCP servers, `FocusDashboard` and the kiosk needed no edits:

**Survivors, and why.** **`Topic`** (`topics`) — a subject, self-FK `parent_id` for subtopics. `salience` float **bumped on write** (`+0.08` clamped to `[0.01,0.99]`), **decayed on read**: displayed = `salience × 0.5^(Δdays_since_last_touched / 7)`, floored `0.01`. No cron — decay is a pure function of `now` (like computing age from birthdate). `color` = per-topic identity (persisted, not meaning). **`b8f3d1c07a45` is the CONTRACT half (2026-08-09) — the four tables are DROPPED.** Only `topics` + `focus_people` remain of the focus schema. Run **`python scripts/verify_focus_convergence.py`** against the target DB before deploying it; it exits non-zero if any source row is unaccounted for, and short-circuits to 0 once the tables are gone. **The deploy is the irreversible step, not the merge** — `alembic upgrade head` runs on uvicorn boot, so shipping the revision drops prod tables. What makes that acceptable is that `upgrade()` **stamps provenance before dropping** and then **refuses to drop unless every row carries it**: one edge per source row recording which v2 row absorbed it, keyed by the ORIGINAL id (`converged_from_thought_batch`/`converged_from_thought` → note, `converged_from_reminder` → promise). The guard lives in `upgrade()` rather than in the verifier script because `alembic upgrade head` runs at uvicorn boot where nobody can invoke a script: a source row with no edge (e.g. a reminder deleted via the dashboard after the expand deploy — `promise_service.delete` wipes the promise *and* every edge touching it) raises, the transaction rolls back, and nothing is dropped. A boot that fails loudly is recoverable; a destroyed row is not. `downgrade()` walks those edges backwards and rebuilds every row with its original id — which is the only way `thoughts.batch_id` and `reminders.thought_id` come back as real FKs instead of dangling integers. Rebuilt rows read the CURRENT v2 state, so connector edits made after the drop survive a rollback. Row visibility follows "is there a whoop payload", NOT "is any metric non-null" — a connected strap silent past the backend's 4-day query window nulls every metric, and metric-gating hid the feed exactly when its death was the news; that state now renders the ambient tile's labelled dashes plus whatever age the stamp can prove (`age unknown` only when there is no usable `source_updated_at`). A never-connected strap (no `date`) still renders nothing. A failed re-fetch keeps the last good reading, same as the tile). Polls `/focus/dashboard` on the shared `FEED_REFRESH_MS` cadence (see the ambient section — `api.ts` owns the number); gcal still merged CLIENT-side. Two-mode light/dark via the LOCAL `focusPalette.ts` (deliberately NOT the app `--gooni-*` vars). **Sparse-state layout (2026-07-29):** the board is a **capped, centred slab** (`BOARD_MAX = min(1440px, 92vw)`), NOT edge-to-edge — the normal state is ~1 short-term promise and a handful of longer-term ones, and stretched across a wide monitor that read as a page that failed to load. Columns are **equal** `1fr 1fr` (the old `1.45fr` gave the most width to short-term on the grounds that it's the column you act on — but a promise is one line of text, so it earns vertical room, not horizontal, while the narrow half carried five stacked panels). Vertical: `justifyContent: "safe center"` on the board wrapper floats the WHOLE slab (chips included — centring only the grid strands them against the top bezel) when content fits, and the `safe` keyword falls back to `start` on overflow so a full board can't be pushed above the scroll origin. The grid is `flex: 0 1 auto` + `overflowY: auto` — **the board scrolls as one**, replacing the old per-column scrollers (two scrollers on a glance surface make the wheel do different things depending on pointer position).

**`▶ focus` → `FocusRunner`** — a session bound to ONE promise. Running screen = the promise text + a clock + a liveness dot, everything else gone; it POSTs `control:running` with `target_reminder_id` so the local sidecar starts sensing (camera opt-in per session — the privacy light is the honest signal). Stop → the report: `focused / present / away / score` from the sidecar's session summary, the day's device pickups, and one action, **mark kept**. With no sidecar alive the session still works — timer + pickups, no cam stats. Unmount ALWAYS clears control, so a closed tab can't leave the camera sensing.

**`/` vs `/focus` now differ.** `/` mounts `FocusDashboard` bare (opening a tab is already the deliberate act). `/focus` mounts **`AmbientShell`** — see the Ambient display section.

**Deadlines (CHANGED 2026-07-29).** Every reminder/promise now carries a `due_at`: the dashboard splits short-term from longer-term on due distance (`focus_service.SHORT_TERM_DAYS = 7`), and a dateless row can't land in either panel. `set_reminder` defaults an omitted due to today's local EOD via `parse_due_hint` (THE one deadline parser) and flags it **`due_is_default`** (migration `b6e4c2a9d713`). That flag is load-bearing, not bookkeeping: `auto_break_overdue` skips defaulted dues, because breaking them would mark Daniel broken at midnight every night on a deadline GOONI invented. A stale defaulted due rolls forward to `today`; an explicit one that passed reads `overdue`. `_due_bucket` compares in LOCAL time — an EOD-anchored due stores as 06:59 the NEXT UTC day, so raw UTC date math files every "today" under "tomorrow". Net: `tests/test_focus_due_bucket.py`. This intentionally reverses the old "promises frequently have no due_at, so they surface by AGE" design; age survives only as display meta for promises owed to other people.

## Ambient display (2026-07-29)

The kiosk monitor stays on **24/7** — a screen that's off is furniture, a sleeping character is presence. So `/focus` is NOT always a dashboard; it's a state machine (`components/focus/AmbientShell.tsx`):

`deep_rest` (away from home) → `rest` (home, Gooni asleep) → `awake` (Gooni up, still NO data) → `dash`.

**`awake` is a real state, not a transition.** Presence alone only rouses him; it does not put Daniel's promises and habits on a screen anyone in the room can read. Data costs a deliberate act. Two clocks drive it: **local** (mouse/key → `awake`, 5min idle → `rest`; kept in the browser because it fires constantly and belongs to that viewport) and **remote** (`GET /display` polled 2s, EDGE-triggered so a stale server value can't stomp a local settle).

- **`Settings.display`** — nullable Text JSON, same Text-not-JSON convention as `focus_cam`. `{desired, at, source}`. `app/services/display_service.py` + `app/routers/display.py` (`GET /display`, `POST /display/control`).
- **Writers are remote and dumb**: an iOS Shortcuts automation on leaving/arriving home, and a **desk button** (NFC tag → Shortcuts → one POST). No new auth path — Shortcuts carries the Bearer like everything else. Same declarative reconcile-poll contract as `/focus/cam/control`, copied on purpose so there's ONE pattern for "a remote thing decides, a local thing catches up".
- **`GooniAsleep.tsx`** — 2D SVG + CSS breathing loop, deliberately NOT the 3D GLTF: this paints 24/7, and a WebGL canvas all night means constant GPU draw, audible fans, and a context that must survive days. Burn-in is handled by slow full-figure drift + low contrast + no static bright shapes; `prefers-reduced-motion` freezes every loop.
- **Monitor power is NOT controlled** — Shortcuts changes *state*, not power. Fly can't reach into the home NAT; if the panel ever genuinely needs to sleep, only the local sidecar can do it (`pmset displaysleepnow`). Specified + gated in the sidecar spec, not built.

**Deferred / gated** (NOT built): displacement notification + hysteresis (`// TODO(displacement)`, `overflow_topics` already plumbed); focus cam (step 6 — the webcam CV **sidecar** is still unbuilt, but its Gooni BRAIN side — ingest endpoints, storage, wall, widget — shipped 2026-07-24, see the Focus-cam section; a SEPARATE daemon from the "Focus cam" seed topic); scheduled reflection/notifications (need cron + API, can't live in a tool call); the API refactor (step 7, separate project — delete Gooni's intelligence layer, real ReAct loop). Host decision (Fly vs idle PC) + connector registration are Daniel's manual steps.

## Focus-cam (2026-07-24 — brain side of the webcam focus sidecar, ADDITIVE)

A local macOS sidecar (built SEPARATELY, not in this repo) watches the webcam, computes focus signals (present/absent, eyes-on-screen, phone-in-hand, hand-to-mouth, standing/left-desk), and reports up to Gooni over Bearer-authed HTTP. Gooni (on Fly, behind home NAT it can't reach into) is pure record + UI: ALL traffic is sidecar-initiated / polling. Start/stop is a **declarative reconcile-poll** — the UI sets desired `control` (idle/running), the sidecar polls `GET /focus/cam` (~2s) and reconciles (self-healing if it was asleep at click time). This pass built ONLY the Gooni side; the CV/VLM/evidence-frames/smart-lights are the sidecar/later.

- **Storage maps onto existing primitives** (NO new tables beyond one Settings column). `Settings.focus_cam` (nullable Text JSON blob, migration `f9c2a7e14b60`) holds the singleton control+live-state: `{control, state, score, app, session_id, at, target_reminder_id}` — Text-not-JSON so the shape grows without migrations. **`target_reminder_id`** binds a run to ONE short-term promise (set by the dashboard's `▶ focus`, cleared on stop); `log_session` stamps it onto the session entry if the sidecar doesn't echo it, so an older sidecar keeps working. Discrete events → +1 on a `"focus {kind}"` sum-agg numeric Trackable (`source=focus_cam`), clock time + dwell/activity/evidence in `value_json`. Per-session summaries → one `focus_session` json Trackable entry per session (full report in `value_json`, day = local `ended_at`) + a `focus_score` numeric mirror. Mirrors the whoop/leetcode json-master + numeric-mirror pattern.
- **`app/services/focus_cam_service.py`** — deterministic (no LLM): blob get/merge/set-control, event + session logging, `today_summary` (the widget read). tz parsing reuses `event_service._parse_at`; days via `local_now`. Singleton via `deps._settings_row`.
- **`app/routers/focus_cam.py`** — `GET /focus/cam` (control+state blob; sidecar reads control, FE reads state + the live preview `frame`/`frame_at`), `POST /focus/cam/state` (live-state merge, on change + ~30s keepalive), `POST /focus/cam/control` (UI Start/Stop), **`POST /focus/cam/frame`** (latest preview thumbnail — base64 JPEG ~320px, LATEST-ONLY overwrite folded into the same Settings blob, 200KB cap; `get_public_blob` re-exposes it on `GET /focus/cam` as a `frame` data: URL + `frame_at`. Freshness = liveness: the widget flips to "offline · not sensing" past ~40s, killing the dead-sidecar-looks-like-RECORDING bug. Full-res VLM evidence frames still stay LOCAL — this is just the low-res liveness preview), `POST /focus/cam/events` (one discrete event), `POST /focus/cam/sessions` (finished session on stop), `GET /focus/cam/today` (widget: sessions + event counts). Namespaced `/focus/cam/*` to stay clear of the Focus SYSTEM's `/focus/*`.
- **HARD WALL — invisible to existing UI.** Every focus Trackable + entry is `source=focus_cam`; `trackable_service.HIDDEN_SOURCES=("focus_cam",)` excludes it from `list_all` (→ `/trackables` matrix/dots columns + overlay `_trackables_today` + chat `read_trackable`) and `activity_service._trackables` filters it from the rail. FE `LogDots.isDaily` also drops it (belt-and-suspenders). Focus data reads ONLY through `/focus/cam/*`.
- **FE** — a **Focus widget** (`FocusCamWidget`, registry `id:focus_cam`, `defaultEnabled:false`) that communicates the SESSION LIFECYCLE at a glance: a pulsing **REC/IDLE badge** (driven by `control`), an **elapsed clock** parsed from `session_id` (`YYYYMMDDTHHMMSS` local; ticks client-side, refresh-safe since all state is server-side), a **big color-coded live state** (FOCUSED/DISTRACTED/AWAY) + graded score (≥70 green / 40–70 amber / <40 red) + frontmost app + a **live preview thumbnail** (`FramePreview`, shown while running: self-ticks 1s, renders the `frame` data: URL when `frame_at` is fresh (≤40s) with "updated Ns ago", else "offline · not sensing" — liveness proof); Start/Stop reflects `control` optimistically. Compact + Panel; Panel keeps today's sessions + event counts (refetched on session end). Polls `/focus/cam` at 2s, `/focus/cam/today` at 10s. Fetchers in `api.ts` (`fetchFocusCam`/`setFocusCamControl`/`fetchFocusCamToday`).
- **Sidecar contract**: `docs/focus_cam_contract.md`. **Out of scope** (design leaves room via loose `value_json` — `activity`/`evidence_id` already in the contract): the sidecar, CV, gated VLM activity labeling, evidence-frame storage, Govee/smart-light control.

## Schema changes (Alembic)

```bash
# After editing app/db/models.py:
source venv/bin/activate
alembic revision --autogenerate -m "what you changed"
# Review the generated file. SQLite quirks: Boolean→INTEGER (cosmetic),
# DateTime→TEXT (cosmetic), missing FK constraints (SQLite doesn't enforce).
alembic upgrade head
# Commit the new revision alongside the model change.
```

`alembic upgrade head` runs on uvicorn boot via `_alembic_upgrade()`. Fresh DBs walk from baseline to head. **Half-applied-state recovery:** boot catches "already exists" OperationalErrors and stamps to head. **Migration-author conventions:** inspector guards (`has_table` / column checks) so re-runs are no-ops; `if_not_exists=True` on create_index. **Dropping columns whose FK targets are already-dropped tables:** batch_alter reflects the table and follows FKs → `NoSuchTableError`; stand up empty phantom parents for the rebuild, drop indexes touching the doomed columns first, drop phantoms after — see `4d9c44f8f546` for the working pattern.

## Code Patterns

- **Zustand persist**: bump key on shape change to avoid stale state
- **Module-style services**: most `app/services/*.py` are function modules (or one instance at bottom)
- **FastAPI `db: Session = Depends(get_db)`** — session per request
- **Optimistic UI**: `createNote` adds temp note, replaces w/ API response
- **React StrictMode**: kept intentionally
- **hasChanges ref**: NoteEditor only saves if the user typed
- **Public routes** `/public` + `/public/$noteId` standalone (no sidebar/auth); grouping label = first tag
- **Deferred embedding columns**: `Note.embedding`, `Note.classified_embedding`, `Memory.embedding`, `Message.embedding`, `Promise.embedding` wrapped in `deferred()`. Similarity callers MUST use tuple queries.
- **Deterministic > LLM** for anything user-facing that ranks/surfaces/promotes (overlay, glow, matchers). LLM only parses.
